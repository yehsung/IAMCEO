# 아키텍처

Bun 서버가 데이터와 AI 세션으로의 전달을 맡고, SwiftUI macOS·iOS 앱이 API를 쓴다. 현재 소스는 `herdr-core`와 공식 대화형 Claude Code·Codex CLI를 연결한다.

IAMCEO는 소스 공개형(Sustainable Use License 1.0 + IAMCEO 추가 허락)이며 [LICENSE](../LICENSE)와 [라이선스 설명](LICENSING.ko.md)을 따른다. 2026-11-10 웹 버전을 제거했다. Mac·iPhone 네이티브 앱과 배포된 앱의 v1/v2 API 호환을 유지한다.

## 구성과 역할

```text
SwiftUI macOS / iOS ── REST sync + WS v2 ─┐
세션 안의 iamceo mcp ─ HTTP /agent/* ────┴─ Bun 서버 ─ SQLite / 첨부
                                             │
                                       Orchestrator
                                             │ CoreRunner / Unix JSON-RPC
                                       herdr-core daemon
                                             │ holder / PTY
                                    공식 Claude Code / Codex CLI
```

- 상태의 원본은 Bun 서버와 SQLite다. 앱은 서버에서 상태를 읽고 사용자 요청을 보낸다.
- core의 holder가 터미널(PTY)과 CLI의 수명을 관리한다. 앱·서버의 종료나 연결 해제로 CLI를 종료하지 않는다. 명시적인 잠재우기·종료·세션 교체는 해당 멤버의 터미널을 끝낸다.
- 일반 `serve` 시작은 IAMCEO 전용 core를 준비한다. 진단 API는 core를 설치·시작·업데이트하지 않는다.
- macOS 앱의 로컬 서비스 등록은 사용자가 `이 Mac에서 시작하기`를 선택했을 때 실행한다. 다른 설치의 서비스·사용 중인 포트·인증 오류를 발견하면 덮어쓰지 않고 오류를 보인다. 소스 빌드만으로 서비스를 등록하거나 시작하지 않는다.

## core와 공식 CLI

기본 core 소켓은 `$IAMCEO_HOME/run/core.sock`, 세션 이름은 `HC_SESSION=iamceo`다. core의 상태·설정은 `$IAMCEO_HOME/core-state`와 `core-config`에 따로 둔다. `IAMCEO_CORE_BIN`·`IAMCEO_CORE_SOCKET`으로 경로를 바꿀 수 있다. 제공자 CLI에는 원래 사용자 HOME·XDG 설정 경로를 넘기고 부모의 외부 `HC_*`·`HERDR_*` 및 Claude 중첩 세션 변수를 제거한다. 호출별 인자와 MCP 설정을 쓰며 전역 CLI 설정 파일은 수정하지 않는다.

core는 `terminal.run`에 셸 문자열 대신 인자 배열을 보낸다. 부모가 종료돼도 CLI는 유지하고, 종료된 명령을 자동 재실행하는 옵션은 켜지 않는다. 서버가 다시 시작되면 프로젝트·멤버·CLI 라벨과 고정 이름으로 기존 터미널을 찾는다. 소유권이 겹치거나 제공자·알려진 세션이 다르면 오류로 처리한다. 소켓 연결이 끊겼다는 이유만으로 새 CLI를 띄우지 않는다.

Claude의 세션 UUID와 core 터미널 주소는 서로 다르다. 새 Codex는 native 세션 ID를 미리 지정할 수 없어 처음에는 `sessionId=null`이다. 실제 사용자 입력의 고유 표식이 유일한 주 세션의 기록과 맞을 때 연결한다. 폴더나 최신 파일만 보고 세션을 고르지 않는다. 기존 터미널을 잃었고 native ID도 모르면 자동으로 새 대화를 만들지 않는다.

옛 실행기 둘(`herdr`·`headless`)은 지웠다. 실행기는 core 하나이고, 서버는 herdr 소켓을 열지 않는다. 남긴 것은 데이터와 API 모양뿐이다: 옛 `backend` 값이 적힌 팀장 행은 그대로 두고, 세션이 남아 있으면 `legacy_session`으로 보류한다. 예전 세션을 core 세션으로 해석하거나 자동 변환하지 않는다. 출시된 앱이 읽는 `backend` 값 목록과 `bootstrap.herdr` 칸은 고정값으로 내려가고, 편입·herdr 목록 주소는 `410`과 안내로 답한다.

## 상태·전달·직접 조작

실행 상태는 `terminal.get`의 OSC 7501 주 세션 기록과 턴 번호로 판단한다. 화면의 글만 보고 작업 중·대기 중·완료를 추측하지 않는다. 상태를 알 수 없으면 자동 입력을 멈추고 설정·신뢰·인증 확인을 안내한다. 단, 턴을 돈 적이 있는 CLI의 상태 기록만 비어 있고 화면에 평소 입력칸이 보이면 끝난 턴으로 읽는다([spec](spec.md)). `terminal.read {lines:0}`으로 읽은 현재 화면은 초안을 보호하거나 사람이 직접 확인하는 데 쓴다.

메시지·결재 답·지시·보고는 `deliveries` 대기열을 거친다. 원본과 전달 의도는 같은 DB 트랜잭션에 저장하고, 전송 전에 고유 표식·본문 해시·세션 세대·기록 기준점을 남긴다. 프로젝트 보관, 실행 꺼짐, 연결 끊김, 진행 중인 턴, 승인 대기, 직접 조작권이 있으면 전달을 보류한다.

CLI의 입력 수락과 업무 완료는 다르다. `started:false` 응답도 입력이 이미 전달됐을 수 있다. 응답 유실 뒤에는 주 세션의 사용자 입력 기록 등 증거를 다시 확인한다. 쓰기 전 실패가 확실할 때만 안전 조건을 확인해 재전송한다. 기록이 없거나 시간이 지났다는 이유만으로 다시 보내지 않는다. 입력칸 전체가 저장된 전달 본문과 일치하고 원래 쓰기가 끝났음이 확인될 때만 제출 키를 한 번 보낼 수 있다. 초안을 지우거나 다시 붙여 넣지 않는다.

스스로 풀리는 조건(2026-11-11 안정성 수정):

- 결과를 모르는 기동은 그 팀장의 터미널이 90초 넘게 보이지 않으면 '뜨지 않음'으로 닫고 다시 깨운다.
- core 실행기는 일하는 턴에 긴급 지시를 끼워 넣지 않고 턴이 끝난 뒤에 보낸다.
- 영수증 없는 쓰기는 전송 호출이 끝나고 30초가 지나면 '끝난 미확인 쓰기'가 된다. 전송 뒤의 세션 기록 전체에 표식이 없고, 입력칸이 비었고, 턴 번호가 그대로일 때만 자동으로 다시 보낸다(최대 3회).
- 기록 파일이 없는 세션은 `--resume` 하지 않고 새 세션으로 연다. 띄우자마자 끝나기를 세 번 이어가면 10분 동안 자동으로 깨우지 않는다.
- 설정 적용 보류는 살아 있는 세션의 전달을 막지 않는다.
- 사용 한도·인터넷 장애로 멈춘 팀장은 간격을 두고 다시 이어 보고, 대표가 새로 말을 걸면 바로 푼다.
- 처리되지 않은 예외는 기록하고 계속 돈다. 10분에 20회를 넘으면 정상 종료 절차로 내려가 서비스가 다시 띄운다.

업무 결과는 `post`·`file` 같은 MCP 도구로 남긴다. core의 턴 종료는 다음 전달을 진행할 신호이며, 화면을 긁어 완료 보고를 만들지 않는다.

터미널 직접 조작은 5분 조작권(lease)을 먼저 확보한다. 이 동안 자동 전달을 멈춘다. v2 요청은 작업 ID·검토한 세션 세대·재사용 가능한 claim ID·입력 순번으로 처리 결과를 기록한다. 결과가 `unknown`이면 같은 입력을 새 ID로 반복하지 않고 기존 결과를 조회한다. 조작권은 서버 재시작 뒤에도 터미널·세대·남은 만료 시간을 복원한다. `iamceo attach <memberId>`의 외부 입력까지 앱 조작권과 완전히 묶을 수는 없으므로 직접 조작 전에 자동 전달을 멈추는 것이 안전하다.

## 제공자·모델·문맥 압축

프로젝트 총괄의 `chiefCli`와 멤버의 `cli`는 각각 `claude|codex`로 저장하며 기본은 Claude다. 현재 소스의 실행 backend는 core다.

제공자나 실행 중인 세션의 모델·effort를 바꾸려면 작업 중·승인 대기·불명확한 전달을 먼저 해결해야 한다. 새 인자를 검증하고 이전 터미널의 종료를 확인한 뒤 세션 이력을 남기고 MCP 토큰과 세대를 바꾼다. 멤버 ID·역할·업무·대화는 유지한다. 이전 종료에 실패하면 제공자와 토큰을 바꾸지 않고, 새 시작에 실패하면 오류를 남긴다.

같은 Claude의 설정 변경은 알려진 native UUID로 이어 연다. 제공자가 바뀌거나 Codex의 native ID를 모르면 새 세션에 역할·현재 일·다음 일·프로젝트 상황을 인계한다. 제공자 간 숨은 추론이나 대화 문맥을 옮기는 기능은 없다. 모델은 멤버별 지정, 적용 가능한 직급 값, CLI 기본값 순으로 고른다. Claude용 직급 설정을 Codex에 그대로 적용하지 않는다.

Claude 병렬 모드는 `/effort ultracode on|off`의 응답을 확인한다. Codex는 자체 서브에이전트 기능과 다음 과제의 병렬·순차 선호를 쓴다. 설정이 실제 하위 실행 개수를 보장하지는 않는다.

core 자동 압축은 같은 세션·세대·모델의 완료 턴에서 최근에 정확히 측정한 문맥 사용량이 기준을 넘고, 실제로 전달할 일이 있을 때 다음 업무 전에 한다. 초안·직접 조작·실행 중인 일·미확인 입력을 무시하지 않는다. 수동 요청은 예약할 수 있다. 입력 수락만으로 압축 완료를 판단하지 않고, 기준점 뒤 압축 기록과 같은 CLI의 안정된 상태 복귀를 확인한다. 전송·실행 중 재시작이나 시간 초과는 결과 불명으로 남기고 재송신과 다음 자동 입력을 막는다.

## 앱 동기화·대화 이력·보관

SwiftUI 앱은 홈·결재함·팀·대화·자료·설정을 제공한다. macOS 14+/iOS 17+와 Swift 6을 대상으로 한다. 지원 OS에서는 Liquid Glass를 쓰고 이전 OS에서는 material 효과를 쓴다.

AppStore의 한 동기화 조정자가 WS v2 변경 알림과 REST 상태 조회를 관리한다. 정상 연결에서는 상태·대화 이력을 3초마다 조회하지 않는다. 변경을 250ms 동안 모아 최대 초당 2회, 동시 1개씩 조회한다. 서버가 느리면 이벤트가 부르는 조회는 직전 조회에 걸린 시간의 2배(최대 5초)만큼 간격을 벌린다. 대표가 누른 새로고침, 쓰기 뒤 조회, 재연결은 기다리지 않는다. 순번이 이어진 message·activity 이벤트는 실린 내용을 그대로 반영하고 대화 페이지·활동 목록을 다시 읽지 않는다. 본문을 읽지 못한 프레임은 연결을 끊지 않고 전체를 다시 읽는다. 순번 누락·서버 세대 변경·재접속 때 상태를 다시 읽는다. WS만 실패하면 REST를 3초마다 조회하고 전체 연결 실패 때는 간격을 최대 30초로 늘린다. iPhone은 앱 비활성·잠금 중에, Mac은 창이 없는 배경 상태와 잠자기 중에 소켓·읽기·재시도를 멈춘다. Mac 앱이 맨 앞이 아니기만 한 경우에는 계속 동기화한다. 열린 터미널 화면은 앱이 활성 상태일 때 별도로 2초마다 읽는다.

접속 코드는 서버 주소별 Keychain에, 주소와 비밀이 아닌 설정은 UserDefaults에 저장한다. HTTPS/WSS를 권장하며 같은 Mac의 loopback HTTP와 기존 Tailscale HTTP 호환도 허용한다. iPhone의 loopback은 Mac 주소가 아니므로 Mac의 Tailscale Serve HTTPS 주소를 사용한다. API 인증을 다른 출처나 HTTP 리디렉션에 넘기지 않는다.

첫 메시지 전송 시도는 호스트·고정 ID·대상·본문·완료된 첨부·초안 버전을 저장한다. 응답 유실이나 앱 재시작 뒤에는 같은 메시지 ID로 접수를 확인한다. 늦은 업로드나 전송 응답이 새 초안을 지우거나 다른 호스트의 초안을 되살리지 않는다. 결재는 읽었던 버전을 보내고 설정·멤버·할 일은 변경 버전을 대조한다. 충돌이나 불명확한 결과를 로컬 성공으로 표시하지 않는다.

대화는 불투명 커서로 처음 200개, 이전 100개씩 읽는다. ID로 중복을 제거하고 늦은 조회가 최신 전달 상태를 덮지 않게 한다. 재접속 사이에 200개 넘게 늘었다면 기존 이력과 연결될 때까지 별도 페이지로 모은다. 실패하면 기존 이력·커서·초안을 보존한다. 이전 글을 붙일 때 현재 보이는 메시지와 스크롤 위치를 유지한다.

보관은 삭제가 아니다. 서버는 재개 가능한 세션 기록과 안전한 종료를 확인한 뒤 보관한다. Codex의 세션 ID를 끝내 확인하지 못하면 409로 보류한다. 직접 붙인 manual 프로세스는 종료하지 않는다. 보관함은 읽기 전용이며 이름 변경·꺼내기는 별도 관리 기능이다. 일반 state/page는 보관 프로젝트에 404를 반환하고 archive 경로로 읽는다. 일반 메시지 목록·주변 조회·단건 조회도 보관 프로젝트에는 404를 반환한다. 보관 메시지는 `/api/projects/:id/archive/messages`와 `/api/projects/:id/archive/messages/:message`로 읽는다. 늦은 manual 보고·자료와 v1 할 일 호환이 있어 보관 데이터가 완전히 고정되는 것은 아니다. 꺼내기는 보관 때문에 보류된 전달만 재검사하며 모든 팀장을 기동하지 않는다.

## iPhone 알림

서버는 데이터 홈의 `apns.json`에 그 앱 번들 ID의 Apple 알림 키가 설정돼 있을 때만 iPhone 알림을 보낸다(`server/push/config.ts`). 키가 없으면 상태는 `unconfigured`이고 아무것도 보내지 않는다. 중계 서버는 없다. 그래서 App Store에서 받은 iPhone 앱은 지금 알림을 받을 수 없고, 직접 빌드한 앱과 자신의 키가 있을 때만 받는다. Mac 앱의 알림은 이와 별개로 Mac 앱이 실행 중에 직접 띄운다.

APNs 발신 대기열은 CLI 입력 대기열과 별개다. 새 기기는 알림이 꺼진 상태이며 사용자가 알림을 켠 뒤 OS 권한·토큰 등록·서버 저장을 확인한다. 새 결재·확인된 승인/선택 대기·오류·완료 보고·대표 할 일·막힘 보고 여섯 종류의 개별 기본값은 모두 켜짐이다. 할 일·막힘 종류가 생기기 전에 등록한 기기는 이 두 종류를 직접 켜기 전까지 꺼짐으로 읽는다.

완료 보고는 같은 프로젝트·팀장의 첫 보고를 바로 알린다. 그 뒤 첫 보고부터 고정 120초 안에 보고가 더 오면 마감에 요약 알림을 한 번 보내고, 더 오지 않으면 다시 알리지 않는다. 마감·보고 ID·처음의 수신 기기 집합을 저장하고 마감을 연장하지 않는다. 재시작에도 같은 마감을 유지하며 새 기기나 다시 켠 기기에 과거 묶음을 보내지 않는다.

서버는 발신 직전에 기기 버전·토큰 세대·선호 종류·유효 기간·원본을 확인한다. APNs 200은 Apple 접수이며 배너나 읽음을 뜻하지 않는다. 쓰기 뒤 결과 불명은 자동 재발신하지 않는다. 알림에는 고정 문구와 불투명 ID만 싣는다. 앱이 열린 동안 수신하면 데이터만 갱신하고, 탭하면 현재 호스트와 대상을 확인한 뒤 이동한다. 알림 탭으로 답·승인·터미널 입력을 실행하지 않는다. APNs 기기 해지는 API 접속 권한 철회가 아니다.

## 인증·자료 안전

무엇을 믿고 무엇을 막지 못하는지는 [보안 설명서](security.md)에 따로 정리했다.

사용자 API는 접속 코드, `/agent/*`는 멤버별 MCP 토큰을 쓴다. MCP 토큰은 멤버 JSON에 내보내지 않는다. 서버는 기본적으로 loopback과 사용 가능한 Tailscale 주소에서 듣고 요청 IP·Host·Origin을 확인한다. 사용자 HTTP·WebSocket·첨부는 Bearer 헤더로 인증하며 URL 접속 코드와 파일 쿠키는 받지 않는다.

`file`·`ask`의 파일 경로는 심볼릭 링크를 따라간 실제 작업 폴더 경계로 검사한다. 비밀 폴더·환경 파일·개인 키·IAMCEO 데이터·다중 하드 링크는 거부한다. 이 검사가 같은 OS 사용자로 실행되는 CLI의 Bash 권한까지 제한하지는 않는다. 실제 도구 권한과 승인은 제공자 CLI가 처리한다.

네이티브 아티팩트는 인증된 서버 render 응답을 비영속 WKWebView에서 연다. 인라인 JavaScript는 허용하고 sandbox CSP와 앱 탐색 정책으로 외부 요청·쿠키·서버 API를 막는다. 자세한 계약은 [구현 계약](spec.md)에 있다.

## 데이터·백업·복원

기본 데이터 홈은 `~/.iamceo`이며 `IAMCEO_HOME`으로 격리할 수 있다.

| 경로 | 내용 |
|---|---|
| `config.json` | 접속 코드·포트·주소·실행 파일 경로, 권한 0600 |
| `iamceo.db` | WAL SQLite의 프로젝트·멤버·결재·할 일·업무·대화·파일·전달·설정과 실행 기록 |
| `iamceo.db.pre-v*.bak` | 마이그레이션 전 DB 백업, 권한 0600 |
| `uploads/`, `inbox/<member>/` | 첨부 원본과 멤버에게 전달할 파일 |
| `roles/`, `run/`, `logs/` | 역할 템플릿, 호출별 규칙·MCP 설정·core 소켓, 서비스 로그 |
| `core-state/`, `core-config/` | IAMCEO 전용 core 상태·설정 |
| `backups/` | 정기 백업(일별 7개·주별 4개) |
| `diagnostics/` | 진단 파일 폴더와 zip, 최근 5개 |
| `cli-versions.json` | 서버가 읽은 Claude·Codex 버전과 처음 본 시각(비밀 없음) |
| `upgrades/<id>/` | `iamceo upgrade`가 남긴 직전 판 기록(plist·DB 사본·이전 앱 또는 커밋) |

데몬은 DB를 열거나 복구하기 전에 홈 단위 OS 잠금을 잡는다. 설정은 권한 0600의 임시 파일에 쓰고 디스크 동기화·이름 교체·디렉터리 동기화를 거쳐 저장한다. 지원하지 않는 미래 DB 버전은 쓰기 전에 거부한다. 기존 DB 마이그레이션 전에는 `VACUUM INTO` 백업을 만들며 실패하면 중단한다.

정기 백업은 기본 24시간 주기로 일별 7개·주별 4개를 보존한다. DB·참조 첨부·설정과 해시·DB 무결성·외래 키를 검사한다. 설정(`config.json`)에는 접속 코드가 그대로 들어 있으므로 백업 사본도 비밀로 다룬다. p8 키·제공자 로그인과 세션 원본·프로젝트 작업 파일은 별도로 보관해야 한다.

복원은 별도 빈 홈만 허용한다. 첨부 경로를 옮기고 프로젝트 실행과 기기 알림을 끄며 미종결 작업을 결과 불명으로 남긴다. 미발신 알림과 열린 보고 묶음은 취소한다. 같은 호스트 복원은 serverId를 유지하고 복제는 새 serverId와 기기 재등록을 사용한다. `outboundEnabled:false`인 복원본은 실행기·HTTP·APNs를 준비하기 전에 서버 기동을 차단한다. 실제 외부 효과와 세션 소유권을 대조한 뒤 서버가 꺼진 복원 홈에서 `iamceo restore reconcile`과 `iamceo restore resume`을 순서대로 실행한다. 재개 허용은 기존 보류 전달의 재전송이나 푸시 기기의 재활성화를 뜻하지 않는다.

로그는 열린 파일을 다시 열어 스트림당 기본 10MiB·현재 파일 포함 5세대로 제한한다. 저장소 정리는 명백히 참조가 없는 실패 임시 파일만 유예·격리 후 처리한다. 보관·초안·완료 첨부·미해결 전달이 참조하는 자료는 보존한다.

접속 코드 교체는 사용자 인증을 거친 실제 loopback 요청만 허용한다. 저장 후 기존 인증·열린 WS·사용하지 않은 연결 QR을 무효화한다. 응답을 잃으면 반복 교체하지 말고 같은 Mac에서 현재 코드를 확인한다. `/api/health`는 생존 확인이고, 인증된 `/api/readiness`는 데몬 준비·실행 버전·DB 버전과 core·주소 연결 진단을 제공한다.

## 시험과 운영 전환

서버 계약 시험은 임시 홈·자동 배정 포트·가짜 실행 파일·전용 소켓을 사용하며 실제 유료 모델을 부르지 않는다. 네이티브 시험은 모의 네트워크와 격리 서버로 계약을 확인한다. 실제 CLI의 입력·압축·복구 의미와 기기 서명·알림은 별도 인수 시험이 필요하다. 실제로 쓰는 서버·데이터 홈·herdr 소켓을 회귀 시험에 사용하지 않는다.

격리 시험, 백업·복원, 접속 코드 교체 절차는 [운영 모델](operating-model.md)을 따른다. core의 버전·출처·서명 보존·업데이트 절차는 [vendor 문서](../vendor/herdr-core/README.md), 앱 실행·빌드는 [native 문서](../native/README.md)에 있다.

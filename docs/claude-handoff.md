# IAMCEO 제품 기획과 구현 인계

2026년 11월 6일 기준. 다음 작업자는 이 문서로 제품 의도와 결정 사항을 파악하고 실제 코드를 확인한 뒤 작업한다. 현재 작업 트리에는 커밋되지 않은 구현과 문서가 많으므로 다른 변경을 되돌리지 않는다.

**사용자는 현재 새로 만든 SwiftUI 디자인을 명확히 거부했고, Claude에게 디자인 개선을 맡기려 한다. 현재 네이티브 화면을 승인된 디자인이나 복제할 기준으로 취급하지 않는다. 다크 계열과 리퀴드 글래스 기반이라는 방향만 유지하고, 레이아웃·밀도·타이포그래피·색·상호작용은 다시 설계할 수 있다.** 사용자가 앞서 좋아한다고 한 것은 기존 웹 프로젝트의 디자인과 화면 구성이다.

## 1. 어떤 제품인가

IAMCEO는 AI를 많이 쓰는 사람이 여러 에이전트에게 병렬로 일을 맡기고 관리하는 개인 업무 시스템이다. 이름은 사용자가 자기 AI 회사를 운영하는 대표라는 생각에서 출발했다.

문제는 여러 에이전트를 실행하는 것만이 아니다. 원격으로 많은 일을 동시에 맡기면 총괄의 보고, 질문, 결과물이 채팅에 쌓여 지금 무엇을 결정해야 하고 어느 일이 막혀 있는지 찾기 어려워진다. IAMCEO는 이를 업무·결재·자료로 구조화하고, 대화는 지시와 논의에 사용한다.

대표가 빠르게 답을 얻어야 하는 질문은 다음과 같다.

- 지금 진행 중인 일과 멈춘 일은 무엇인가?
- 내 결정이나 답변이 필요한 일은 무엇인가?
- 내가 직접 해야 할 일은 무엇인가?
- 결과물과 근거는 어디에 있는가?
- 해당 업무나 담당자에게 추가 지시를 어떻게 전달하는가?

비개발자도 설치와 연결을 이해할 수 있어야 하지만, 숙련된 AI 사용자에게 필요한 모델 선택·병렬 작업·터미널 접근을 없애는 제품은 아니다. 회사 비유는 역할과 책임을 이해시키는 수단이며, 고정 조직도나 불필요한 결재 단계를 만드는 목적이 아니다.

## 2. 사용자가 결정한 방향

| 항목 | 결정과 이유 |
|---|---|
| 실행 엔진 | herdr-core 하나로 통일. herdr / headless / 상주 headless를 사용자가 고르는 구조를 없앤다. |
| 모델 실행 | 공식 Claude Code·Codex 대화형 CLI를 사용한다. 기존 로그인·도구·설정·세션 동작을 활용한다. |
| 구독 사용 | 사용자의 CLI 로그인과 구독 경로를 활용하려는 방향이다. 모든 제공자·계정의 구독 사용 가능 여부나 한도를 IAMCEO가 보장하는 것은 아니다. |
| 총괄 | 기본 Claude. 프로젝트를 처음부터 Codex 총괄로 시작하거나 이후 교체할 수 있다. |
| 팀장 | 맡은 업무에 따라 여러 명 생성하고 각각 Claude/Codex를 선택한다. 개발 팀장 한 명 밑으로 모든 작업을 몰아넣지 않는다. |
| 모델 변경 | 제공자 간 완전한 내부 컨텍스트 이전을 전제로 하지 않는다. 새 세션에 업무를 인계하는 방식이 허용됐다. 별도 팀장을 추가하는 것도 자연스러운 사용 방식이다. |
| 프런트엔드 | SwiftUI 네이티브 macOS·iOS부터 개발. 플랫폼 사용성을 우선하며 기존 TypeScript 프런트 재사용에 선택을 종속시키지 않는다. |
| 플랫폼 일관성 | Mac과 iPhone에서 같은 업무·결재·담당자·대화·자료에 접근한다. 배치는 각 플랫폼에 맞춘다. |
| 원격 연결 | 각 클라이언트가 호스트 데몬에 직접 연결한다. 모바일에서 Mac 앱 화면을 축소하거나 중계하지 않는다. Tailscale을 활용한다. |
| 향후 플랫폼 | Windows·Android 지원을 염두에 두되 현재 구현 대상은 아니다. |
| 디자인 | 다크 계열, 리퀴드 글래스 기반. 현재 새 SwiftUI 디자인은 재설계 대상이다. 보라색 자체나 현재 카드 배치는 확정 요구가 아니다. |
| 라이선스 | 2026-11-07 소유자 결정으로 소스 공개형으로 바꿨다: Sustainable Use License 1.0 + IAMCEO 추가 허락(도구로 쓰기·결과물 상업 이용, 유료 설치·지원 대행 허용). OSI 오픈소스로 소개하지 않는다. 그 전에 공개된 버전(v0.1.0 등)은 AGPL-3.0-only로 남는다. 설명은 docs/LICENSING.ko.md. |

herdr-core는 기존 Herdr TUI 프로젝트와 구분해야 한다. 현재는 고정 버전의 공식 바이너리와 서명된 Herdr Core.app을 번들에 넣고 IAMCEO 어댑터로 제어한다. upstream 소스 전체를 IAMCEO에 복사해 자체 포크한 상태는 아니다. Paseo는 클라이언트가 데몬에 직접 붙는 방식의 참고 대상이었고 현재 엔진 의존성은 아니다.

## 3. 조직과 컨텍스트 운용

대표는 목표를 주고 결정한다. 프로젝트별 총괄은 일을 나누고 담당자를 선정하며 보고를 종합한다. 팀장은 실행을 맡고, 필요하면 해당 CLI의 서브에이전트를 활용한다. 기존 데이터 모델의 `worker`가 화면에서는 주로 팀장에 해당한다. 본사 AI `root`는 프로젝트 생성과 프로젝트 밖 요청을 담당하는 기존 개념이다.

총괄이 작은 수정까지 위임하도록 한 이유는 총괄의 컨텍스트에 코드 탐색·도구 로그·구현 세부사항이 쌓이는 것을 줄이려는 것이다. 총괄은 이미 올라온 보고를 반복하기보다 판단과 다음 조치를 남긴다. 이 운영 규칙은 역할 프롬프트의 지침이며 모델 행동을 완전히 강제하는 보안 경계가 아니다.

담당자는 업무와 맥락에 따라 나눈다. 같은 파일을 바꾸는 작업은 충돌을 피하도록 조정하고, 독립된 작업은 다른 팀장에게 병렬로 맡긴다. 임의로 개발·검토·조사 세 팀만 고정 생성하는 구조를 요구한 것이 아니다. 현재 워크스페이스 격리·파일 소유권 충돌 방지가 전부 서버에서 강제되는 것은 아니다.

현재 세션 교체는 멤버 ID와 업무 기록을 유지하면서 이전 세션 이력과 토큰을 회전하고 새 CLI를 연다. 인계문에는 역할·현재 일·다음 일·프로젝트 상태와 `board` 조회 안내가 들어간다. 모든 대화·파일을 분석해 완전한 인계 요약을 만드는 기능은 아니다. 제공자의 내부 추론, 캐시, 압축 상태가 다른 제공자로 이전되지는 않는다.

같은 Claude의 설정 변경은 알려진 native 세션 UUID를 재개할 수 있다. Codex는 새 세션의 native ID를 아직 자동 탐색하지 않으므로, 살아 있는 core 터미널에는 다시 붙을 수 있지만 그 터미널을 잃으면 명시적인 **새 세션으로 이어가기**가 필요하다. 작업 중·승인 대기·전달 불확실 상태에서는 교체를 막는다.

## 4. 화면의 역할

현재 메뉴는 홈·결재함·팀·대화·자료이며 설정은 별도로 제공한다. 이름과 세부 배치는 재검토할 수 있지만 두 플랫폼의 기능 범위를 다르게 만들지 않는다.

| 화면 | 사용자가 하는 일 | 디자인에서 유지할 기능 |
|---|---|---|
| 홈 | 병렬 업무를 훑고 지금 개입할 곳으로 이동 | 현재 상황, 결정 대기, 내가 할 일, 담당자 상태, 업무 진행, 최근 보고·자료와 해당 상세로 이동 |
| 결재함 | 판단·선택·정보 요청에 응답 | 배경·근거·첨부·선택지 결과·추천·메모·명시적 제출. 처리한 항목과 보류/변경 상태 구분 |
| 팀 | 업무 담당자와 실행 세션을 관리 | 총괄·팀장·CLI 제공자·모델·상태·현재/다음 일, 생성, 설정 변경, 복구, 직접 대화, 터미널 접근 |
| 대화 | 새 지시와 추가 논의를 전달 | 프로젝트/개별 담당자 대상, 첨부, 전송 상태, 실패·보류 안내, 대상별 작성 중 초안 |
| 자료 | 결과물을 확인하고 비교 | 제목·요약·작성자·본문·이미지·첨부·HTML 자료, 검색과 관련 업무로 이어지는 맥락 |
| 설정과 연결 | 호스트·실행 설정을 관리 | 로컬 시작, 원격 주소·접속 코드, 실행 환경 진단, 권한·모델 설정, 연결 오류 |

### 결재함에 들어가는 것

사용자가 판단해야 하는 선택뿐 아니라 “이 정보를 알려주면 계속 진행할 수 있습니다” 같은 질문도 포함한다. 로그인·실물 확인처럼 사용자가 직접 수행해야 하는 행동은 현재 `todo`로 구분한다. 화면에서 이를 함께 묶어 보여줄 수 있어도 **결정에 답한 것과 직접 작업을 완료한 것의 데이터 의미**를 혼동하지 않는다.

업무 결재 `ask`와 CLI 자체 권한 승인 메뉴도 다르다. 현재 core의 CLI 메뉴는 팀원 터미널의 명시적인 직접 조작으로 처리한다. 모든 CLI 권한 요청이 자동으로 구조화된 결재 카드로 변환되는 구현은 없다. 이를 하나의 주의 항목 목록으로 통합하려면 추가 구현이 필요하다.

### 디자인 개선 시 특히 중요한 점

- 사용자가 원하는 것은 병렬 업무를 정리하는 화면이다. 대화 목록이나 거대한 요약 카드만으로 대부분의 공간을 채우지 않도록 검토한다.
- 현재 수치·상태·다음 행동을 빠르게 읽을 수 있는 밀도를 찾는다. 작은 화면에서도 결정 근거와 영향은 생략하지 않는다.
- 담당자의 CLI 실행 상태와 업무 완료 상태는 구별한다. idle은 업무 완료 증거가 아니다.
- 글래스는 구분과 계층을 돕는 표현이다. 대비, 한글 가독성, 선택·포커스·오류 상태가 먼저다.
- 데스크톱은 넓은 작업 공간과 비교·상세 탐색을, 모바일은 짧은 확인·결정·추가 지시를 지원한다. 모바일에서도 핵심 관리는 가능해야 한다.
- 최신 SwiftUI 화면과 HTML 시안은 구현 참고 자료일 뿐 사용자에게 승인된 시안이 아니다. 현재 사용자가 싫어하는 이유를 임의로 단정하지 않는다.

## 5. 전체 아키텍처

```text
Mac SwiftUI 앱 ───────────────┐
                            │ REST + Bearer 접속 코드
iPhone SwiftUI 앱 ────────────┤ 원격: Tailscale Serve HTTPS
                            ▼
                     IAMCEO 데몬
                     Bun / TypeScript
                     HTTP API + Orchestrator
                        │           │
                        │           └── SQLite / 첨부 파일
                        │
                        └── CoreRunner
                              │ Unix socket JSON-RPC
                              ▼
                         herdr-core
                              │
                        holder / PTY
                              │
                    공식 Claude / Codex CLI
                              │ stdio MCP
                              ▼
                        iamceo mcp
                              │ 멤버별 토큰 / HTTP
                              └── IAMCEO 상태·질문·보고·자료 도구
```

기존 React 웹은 같은 서버의 REST·WebSocket을 사용하며 이행 기간에 남아 있다. 새 네이티브 앱은 현재 전경에서 3초마다 조회한다. 네이티브 WebSocket 구독과 백그라운드 APNs는 미구현이다.

| 영역 | 스택과 책임 |
|---|---|
| 화면 | Swift 6·SwiftUI. macOS/iOS 공용 상태·API 모델, 플랫폼별 배치. HTML 자료는 WKWebView |
| 도메인 서버 | Bun·TypeScript. 프로젝트·멤버·결재·메시지·전달 큐와 멤버 수명 관리 |
| 저장소 | SQLite WAL, 업로드 파일, 이전 세션 이력. 기본 `~/.iamceo` |
| 실행 | herdr-core 0.1.18, generation 1, 별도 holder가 공식 CLI의 PTY 소유 |
| 연결 | 로컬 HTTP, 원격 네이티브는 HTTPS. Tailscale Serve를 통한 호스트 연결 |
| 인증 | 사용자 접속 코드, 멤버별 MCP 토큰. 네이티브 접속 코드는 endpoint별 Keychain |
| Mac 배포 | 네이티브 앱 안에 컴파일된 IAMCEO 데몬·공식 서명 core·라이선스 포함. 로컬 호스트 시작 시 launchd |

앱을 닫거나 폰의 연결이 끊겨도 호스트에서 CLI가 계속 실행되는 것이 목표다. core 서버 재시작 시 실제 Claude·Codex PID가 유지되는 것은 검증했다. 호스트 잠자기·전원 종료·재부팅 중에도 작업이 계속된다는 뜻은 아니다.

공식 CLI를 쓰므로 각 CLI의 설정·인증·도구 경로를 유지한다. 캐싱이나 성능이 항상 같거나 더 좋다는 비교 실험은 하지 않았다. IAMCEO가 별도의 추론 엔진이나 캐시를 재구현하지 않는 것이 설계 의도다.

## 6. 주요 동작 흐름

### 지시와 병렬 실행

1. 대표가 프로젝트 총괄 또는 특정 팀장에게 지시한다.
2. 서버가 메시지와 전달 항목을 저장한다. 같은 메시지 ID 재시도로 중복 기록을 만들지 않는다.
3. 실행·연결·세션 상태와 직접 조작권을 검사한 뒤 해당 CLI에 전달한다.
4. 총괄은 역할에 맞는 팀장에게 위임한다. 팀장은 `status`로 현재 일을 남긴다.
5. 팀장은 필요할 때 CLI의 서브에이전트를 쓰고, 결과를 `post`·`file`로 남긴다.
6. 대표는 채팅 전체를 다시 읽지 않고 홈·팀·자료에서 결과와 개입할 일을 확인한다.

Claude 병렬 설정과 Codex 서브에이전트 설정·과제 지침은 별도 구현이다. 두 CLI의 모드와 실제 하위 에이전트 실행 수가 같다고 가정하지 않는다. 자동 Git worktree 격리나 완전한 병렬 충돌 해결까지 구현됐다고 보지 않는다.

### 결정과 답변

1. 담당자가 `ask`로 배경·선택지·추천·근거를 남긴다.
2. 사용자가 결재 상세를 읽고 선택 또는 자유 답변을 작성한다.
3. 명시적으로 제출할 때 검토했던 버전을 `expectedVersion`으로 보낸다.
4. 검토 중 내용이 바뀌면 선택을 초기화하고 재검토를 요구한다. 작성한 메모는 보존한다.
5. 답은 질문한 담당자에게 전달된다. 총괄이 사용자의 결정 내용을 바꾸는 중간 단계가 아니다.

### 터미널 직접 조작

원격에서 신뢰·로그인·권한 메뉴가 나오면 팀원 터미널 화면을 열고 직접 조작권을 얻는다. 이 동안 자동 입력을 중단한다. lease는 5분이며 입력 시 갱신된다. 현재 네이티브 터미널은 화면 텍스트 조회와 입력·키 버튼이며 완전한 스트리밍 터미널 에뮬레이터는 아니다.

OSC 7501 상태로 실행 상태를 읽는다. 입력 화면도 초안 보호를 위해 읽지만 화면 문구를 업무 완료 보고로 해석하지 않는다. 응답을 잃어 전달 여부를 모르면 자동 재전송하지 않는다. 외부 `iamceo attach` 입력과 앱의 조작권을 완전히 원자적으로 통제할 수는 없다.

### 호스트 컴퓨터와 결과물

CLI에 이미 연결된 도구가 호스트 앱·브라우저·시뮬레이터를 다루고 캡처를 만들면, 그 결과를 IAMCEO 자료나 첨부로 전달하는 방향이다. IAMCEO 안에 범용 컴퓨터 조작 엔진을 새로 구현한 상태는 아니다. 특정 도구의 설치·권한·기능까지 모든 CLI에서 자동 제공되는 것도 아니다.

## 7. 실제 구현과 남은 범위

| 구분 | 현재 상태 |
|---|---|
| core 단일 실행기와 CLI 제공자 어댑터 | 구현. Claude·Codex 실제 입력→MCP 상태 갱신→완료 보고 확인 |
| 총괄·팀장 선택과 세션 교체 | 구현 및 계약 테스트. 교체 시 내부 컨텍스트 전체를 이전하지 않음 |
| 세션 이력·토큰 회전·DB 마이그레이션 백업 | 구현. 기존 사용자 DB를 실제로 마이그레이션한 것은 아님 |
| 주요 API | 프로젝트·멤버·결재·메시지·첨부·자료·설정·터미널 제어 구현 |
| SwiftUI macOS·iOS | 구현·빌드 성공. 디자인은 사용자 재설계 요청 상태 |
| Mac 앱 직접 조작 | 샘플 모드에서 화면 전환·상세·선택·대상 대화·자료 열기 확인 |
| 실제 네이티브 네트워크 | Swift URLSession→격리한 실제 데몬으로 인증·프로젝트·결재·첨부·자료·메시지 검증 |
| Mac 처음 설치 | 번들·로컬 시작 기능 구현. 깨끗한 Mac의 전체 최초 설치 흐름 미검증 |
| iPhone 실기기와 외부 원격 | 서명·실기기 설치·장시간 원격 운용 미완료. Xcode의 iOS Signing & Capabilities와 계정 로그인 창까지 열어둔 상태였으며 로그인 완료를 가정하지 말 것 |
| 푸시와 동기화 | APNs·네이티브 WebSocket 미구현. 전경 3초 폴링 |
| 자료 렌더링 | 네이티브 HTML은 JavaScript·외부 요청 차단. 웹과 모든 렌더링 능력이 같지는 않음 |
| 세션 복구 | 살아 있는 core 터미널 재결합. Codex native ID 탐색과 손실 세션 자동 재개는 제한 |
| 문맥 관리 | core 자동 압축 미지원. 컨텍스트 사용량·서브에이전트 수가 모든 제공자에서 정확히 수집된다고 가정하지 말 것 |
| 운영 안정성 | 대규모 병렬·장시간·네트워크 단절·재부팅 복구의 충분한 실사용 검증은 남음 |

기존 실행 권한 기본값은 `bypassPermissions`로 유지되어 있다. UI가 이를 안전한 sandbox 실행처럼 표현하면 안 된다. 세션은 호스트 사용자 권한으로 실행되며 설정에서 CLI 권한 모드를 고를 수 있다.

최근 기록은 서버/로직 553개, 웹 165개, Swift 14개 테스트 통과다. 모의 실행 테스트도 포함되므로 장기간 실사용 안정성의 보증으로 쓰지 않는다. 정확한 검증 범위와 재시도 결과는 [검증 기록](native-verification.json)을 확인한다.

## 8. 디자인 변경 때 지켜야 할 기능 계약

- 실제 연결 전에는 실데이터처럼 샘플을 표시하지 않는다. 샘플 모드는 명확히 구분하고 쓰기를 막는다.
- 제출 성공, 큐에 저장, CLI에 전달, CLI 턴 종료, 업무 완료를 하나의 성공 상태로 합치지 않는다.
- 연결 끊김·불확실한 전송·작업 중·승인 대기·직접 조작 중 상태와 다음 행동을 보여준다.
- 대상이나 프로젝트가 바뀌어도 작성 중 초안을 다른 담당자에게 잘못 보내지 않는다.
- 오래된 결재에 답하지 않도록 버전 검증과 명시적 제출을 유지한다.
- 제공자 변경이 새 세션 인계라는 사실과 실패 상태를 숨기지 않는다.
- 접속 코드를 URL·로그·HTML 자료에 넘기지 않는다. 첨부는 인증된 같은 origin에서만 받는다.
- UI 개선만을 위해 엔진 선택지를 다시 만들거나 가짜 정상 연결·가짜 작업 성공을 넣지 않는다.
- 승인된 액션을 위한 기존 서버 동작을 임의로 바꾸지 않는다. 디자인 개선과 동작 변경은 구분해 설명한다.

## 10. Claude에게 요청할 작업

1. 기존 웹 화면과 현재 SwiftUI 구현을 직접 읽고 제품의 정보 구조를 파악한다.
2. 병렬 업무 관리·내 결정·결과물 확인·추가 지시를 기준으로 새 디자인 방향을 잡는다. 현재 화면의 색이나 카드만 바꾸는 범위에 묶이지 않는다.
3. Mac과 iPhone에서 같은 업무를 처리하는 대표 흐름을 함께 설계한다. 충분히 실제적인 병렬 업무·질문·오류 사례로 검토한다.
4. 기존 API와 기능 계약을 유지하면서 네이티브 UI를 개선한다. 자료 구조나 API 변경이 필요한 부분은 별도 동작 변경으로 설명한다.
5. 기존 테스트와 빌드를 확인하고, 실제 화면에서 가독성·탐색·입력·상세·오류·빈 상태를 검증한다. 미구현 기능을 화면만으로 완료 처리하지 않는다.

디자인 개선이 현재 요청의 중심이다. 운영 안정성·푸시·서명 등 남은 기능을 이 문서만으로 전부 추가 구현하라는 별도 지시로 해석하지 않는다.

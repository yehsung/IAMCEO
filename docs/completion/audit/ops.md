## 요약

- **데이터 복구가 마이그레이션 직전 DB 사본에만 의존한다.** 정기 백업·첨부 포함 복원·손상 검증·복원 실행 경로가 없다. (01~03)
- **포트를 바꾸면 같은 데이터 폴더로 데몬 두 개를 실행할 수 있다.** 프로세스 내부 잠금만으로는 큐·터미널·직접 조작권의 이중 소유를 막지 못한다. (04)
- **디스크 부족과 저장소 증가를 시스템이 관리하지 않는다.** 업로드·자료·백업·로그가 쌓이고, 부분 저장과 고아 파일을 사람이 찾아야 한다. (05~07, 11)
- **IAMCEO가 살아 있어도 core가 죽거나 재결합에 실패하면 자동 회복이 끊긴다.** 서버 자체 사망은 전경 앱을 열기 전까지 알 수 없고 `/api/health`는 준비 상태를 증명하지 않는다. (08~10)
- **접속 코드의 안전한 저장·기기별 철회·짝 맺기 응답 유실 복구가 부족하다.** Tailscale 바인딩도 최초 실패/주소 변경 뒤 실제 접근 가능성을 재검증하지 않는다. (12~15)

감사일: 2026-11-07. `docs/claude-handoff.md` 전체를 먼저 읽고 작업 트리의 서버·CLI·설치/빌드 스크립트·네이티브 서비스를 정적으로 대조했다. 아래 줄 번호는 감사 시점 기준이다. 코드는 수정하지 않았으며 이 보고서만 작성했다. 라이브 7878·`~/.iamceo`·herdr 소켓에 접근하지 않았고 실제 CLI 세션·서비스·테스트·빌드는 실행하지 않았다.

소유자 지시대로 라이브는 herdr로 취급한다. 다만 **작업 트리의 `createOrchestrator`는 core 하나만 생성**한다(`server/orchestrator.ts:438-443`). 따라서 라이브 바이너리와 이 트리가 같다고 가정하지 않았다. 공통 저장소/운영 결함과 core 목표 경로를 우선 평가하고, herdr의 기존 복구 장치는 비교 근거로만 사용했다. 별도 설계 중인 전달 판정·복구, 실시간 동기화, APNs, 대화 이전 기록, 프로젝트 이름·보관, core 문맥/압축은 새 기능으로 중복 제안하지 않는다. 웹 전용 문제는 제외했다.

## 우선순위 제안

**완성 전에 꼭**

1. **데이터 홈 단일 소유권(04)을 먼저 확정한다.** 백업·GC·업데이트·복구가 모두 이 배타 경계를 사용해야 한다. 합격 기준은 같은 홈/다른 포트의 두 번째 데몬이 DB/recovery/외부 실행 전에 거절되는 것이다.
2. **데이터 보호 최소선(01~03, 05, 12)을 만든다.** 정기 DB+첨부 백업, 검증된 복원, 미래 스키마 거부, 무결성 이상/디스크 임계 시 쓰기 중단, 원자적 config 저장을 포함한다. 백업 파일 생성 성공만으로 완료 처리하지 않는다. 격리 환경에서 손상 DB·첨부 누락·저장 실패·중간 이주 실패·구버전 재시작을 검증해야 한다.
3. **core 회복과 준비 상태(08~10)를 연결한다.** core 부재/연결 장애/소유권 충돌을 구분하고, 일시적 실패 후 기존 터미널을 재결합한다. 기동/서비스 등록/업데이트 완료는 실제 readiness로 확인한다. 서버/호스트 사망은 별도 관측자가 알아야 하며, APNs 구현 완료가 이를 대신하지 않는다.
4. **기기 접근 철회(13)와 로그 상한(11)을 최소 운영 기능으로 둔다.** 분실 기기 하나만 차단하면서 정상 기기는 유지되는지 검증한다. 로그는 반복 장애를 넣어 디스크 상한과 진단 보존이 동시에 지켜지는지 확인한다.
5. **첨부의 부분 저장 정리(06), 최초 실패한 명시적 bind 재시도(15)를 막힘 없는 기본 동작으로 만든다.** 사용자에게 성공으로 응답한 파일이 재시작 뒤에도 열리고, 네트워크가 늦게 준비되어도 수동 서버 재시작을 요구하지 않아야 한다.

**완성 후**

- 06의 자료 게시까지 포함한 영속 operation ID/receipt와 14의 기기 키 기반 짝 맺기 재시도, 07의 전체 참조 인벤토리/보수적 GC를 확장한다. 그 전에도 실패 중 생성된 임시 슬롯은 추적·정리하고 사용량은 보여야 한다.
- 15의 주소 교체·네트워크 전환 장기 시험, 10의 버전별 설치/원클릭 복구를 다듬는다. core 업그레이드 시 holder 유지 가능 여부는 별도 검증 후 정책화한다.
- 자동 복구 시험은 임시 데이터 홈·포트 0·mock core/herdr·가짜 CLI·mock launchctl/파일시스템 오류로 수행한다. 실제 사용자 환경·7878·라이브 소켓은 시험 대상으로 삼지 않는다. 이번 감사에서는 그 시험을 실행하지 않았다.

**하지 말 것**

- 백업을 위해 WAL DB 본체만 단순 복사하거나, 검증 없이 가장 최신 사본을 원본 위에 덮어쓰지 않는다. 복원된 전달 큐를 자동 전량 재전송하지 않는다. (01~03)
- core hello timeout만으로 holder/CLI를 죽이거나 Codex를 새 세션으로 자동 교체하지 않는다. 라이브 herdr의 재시도/전달 정책이나 기본 실행기를 이 감사의 후속 소규모 보강에 섞지 않는다. (08, 10)
- APNs·실시간 동기화·전달 확인·대화/프로젝트 관리 설계를 다시 제안하지 않는다. 특히 전달 unknown의 자동 해소는 해당 별도 설계의 증거 계약을 따르고, 여기서는 운영 소유권/복원 시 중복 방지 경계만 보강한다. (04, 09)
- 나이/확장자/직원 삭제만 근거로 자료·첨부·inbox를 지우지 않는다. 새 QR을 다시 만들게 하는 현재 동작을 고치려고 일회용 코드를 누구에게나 재사용 가능하게 만들지 않는다. (07, 14)
- launchd 등록 성공·PID 존재·`/api/health` 200·QR 생성만으로 서비스 정상이나 원격 연결 성공을 표시하지 않는다. (09, 10, 15)

## 확인 못 한 것

- **라이브와 배포 상태:** 라이브 7878, `~/.iamceo` 전체(특히 config.json), 실제 herdr/core 소켓·로그·launchd job은 조회하지 않았다. 라이브가 어떤 커밋/바이너리를 사용하는지, 외부 백업·감시·OS 로그 회전·Tailscale Serve가 별도로 설정돼 있는지 모른다. 따라서 “구현 경로가 없다”는 판단은 이 저장소 범위다.
- **실제 장애 빈도/규모:** DB/첨부/로그 사용량, OS의 빈 공간, 손상 이력, 여러 데몬을 동시에 띄웠던 사실, 사용자 기기의 분실/코드 유출은 확인하지 않았다. 04의 이중 실행과 05의 부분 실패는 코드에서 가능한 경합/실패 경로이며 발생 사실 보고가 아니다.
- **운영 환경 효과:** core 내부 holder·스냅샷·디스크 정리·socket 권한은 upstream 구현/실행 환경까지 감사하지 않았다. 주소 소멸/복귀 때 Bun listener가 실제로 어떻게 회복되는지, Tailscale Serve 프록시 뒤의 rate limit이 어떤 source IP로 묶이는지도 미검증이다. 이를 확인하기 위해 라이브에 접속하지 않았다.
- **보안 경계:** 코드 생성·파일 0600·QR TTL/일회성·IP별 실패 제한은 이미 있다(`server/config.ts:41-47`, `server/pairing.ts:5-9,23-62`). Keychain의 endpoint 분리와 일반 API의 redirect/외부 첨부 origin 차단도 구현돼 있다(`native/Sources/IAMCEO/Services/KeychainStore.swift:4-24`, `APIClient.swift:28-48,79-85`). 이를 미구현으로 보고하지 않았다. CLI가 동일 OS 사용자 권한으로 실행되는 기본 구조를 이 감사에서 sandbox로 간주하거나 바꾸도록 제안하지 않았다.
- **기존 검증의 한계:** 이주 사본의 옛 행/스키마/0600을 확인하는 테스트는 존재한다(`tests/server-runtime.test.ts:164-188`). QR 일회성과 제한 시험도 있다(`tests/pairing.test.ts:15-55`). 읽었지만 실행하지 않았으며, 정기 복원·ENOSPC·다중 데몬·업데이트 rollback이 검증됐다는 근거로 확대하지 않았다.
- **빌드/변경 범위:** 보고서만 작성했으므로 TypeScript 컴파일·Swift 빌드·테스트는 실행하지 않았다. 컴파일 에러가 없다는 새 검증 결과를 주장하지 않는다. 라이브 관련 동작을 유발할 실행 명령이나 git 상태 변경은 수행하지 않았고 새 라이브러리/의존성도 사용하지 않았다.

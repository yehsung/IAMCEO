## 판정표

검증 기준: 2026-11-07 작업 트리. 원 보고서의 발견 10개를 호출부·실행기·Store·관련 `tests/`와 대조한 정적 검증이다. 아래 ‘확인’은 코드상 도달 가능한 실패 경로의 확인이며 라이브 재현을 뜻하지 않는다. 시험은 소스를 읽었으며 실행하지 않았다. 추가 파일 생성을 피하기 위해 빌드·타입 검사도 실행하지 않았다. 라이브 7878·`~/.iamceo`·herdr 소켓·실제 Claude/Codex 세션에 접근하지 않았고 git 상태를 변경하지 않았다.

별도 설계서는 구현된 방어로 세지 않았다. 발견 전체가 별도 작업과 겹치면 ‘중복’, 독립된 결함이 남으면 ‘부분’으로 두고 겹치는 개선 범위를 명시했다. 실시간 동기화는 클라이언트↔서버 연결(`.pumasi/specs/realtime.md:24–27`), APNs는 알림 발신(`.pumasi/specs/apns.md:5`), 이전 기록은 저장된 메시지 조회(`.pumasi/specs/chat-paging.md:5`)여서 core 실행 복구의 대체 경로가 아니다. 웹 전용 발견은 없다.

## 확인된 핵심

- 1·2: 소유 core 기동 실패 후 회복과 큐 없는 활성 멤버의 재결합을 연결하되, 살아 있는 holder를 새 CLI로 대체하지 않는다.
- 3: 새 종료 보고 없이 사라진 진행 턴을 조용히 버리지 않고 중단 여부·기존 보고를 대조해 한 번 알린다; delivered 입력의 무조건 재전송은 하지 않는다.
- 6: 최초 실행 응답 유실·paneId 저장 전 종료에도 같은 memberId의 생성 의도를 보존해 명부 밖 실행을 만들지 않는다.
- 7: 일반 sleep/close의 stop 거부·응답 유실에서 asleep/closing을 확정 상태로 남기지 않고 재시작 뒤에도 종료 의도를 확인한다.
- 10: 서버 재시작으로 직접 조작권의 남은 유효시간이 사라져 자동 입력이 재개되지 않게 한다.

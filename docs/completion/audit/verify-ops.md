## 확인된 핵심

- **04 — 데이터 홈 단일 소유권:** 같은 홈·다른 포트의 두 번째 데몬을 DB/recovery/직접 조작권 획득 전에 차단해야 한다.
- **01 — 복구 가능한 데이터 사본:** 이주 사본 외에 DB·참조 첨부의 정기 보존과 검증된 복원 절차가 있어야 한다. 앱 내 자동 복원 전체를 먼저 만들 필요는 없다.
- **03 — 미래 스키마 거부:** 지원하지 않는 DB를 구버전 바이너리가 정상적으로 열었다고 반환하지 않게 해야 한다. 단계별 이주 자체는 유지한다.
- **05·06·12 — 저장 실패의 최소 안전선:** 저장장치 오류를 식별하고 실패 게시의 잔여물을 추적·정리하며 config를 원자적으로 저장해야 한다. 전체 GC·자료 게시 영수증 시스템은 후속 확장이다.
- **08 — core 회복 공백:** 소유 core 부재와 시작 시 재결합 실패를 안전하게 재시도해야 한다. 이미 동작하는 track 폴링과 전달 unknown의 재전송 금지는 유지한다.
- **10 — CLI 완료 판정:** 등록·업데이트의 성공을 실제 인증된 준비 확인으로 연결하고 kickstart 실패를 숨기지 않아야 한다. Mac의 기존 bootstrap 대기는 재사용할 수 있다.
- **11 — 로그 상한:** 반복 장애가 고정 로그 파일을 끝없이 키우지 않도록 보존량 제한이 있어야 한다.

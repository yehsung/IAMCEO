# 문제 해결

[English](troubleshooting.en.md) · [사용자 문서 목록](README.md)

아래 `iamceo`는 앱 안의 명령줄 도구(`/Applications/IAMCEO.app/Contents/Resources/runtime/iamceo`)입니다 → [시작하기](getting-started.md#명령줄-도구)

## 먼저 점검표를 봅니다

IAMCEO가 스스로 실행 환경을 점검합니다. 항목마다 상태와 고치는 법을 한 줄씩 보여 줍니다.

- **앱:** 설정 → AI 모델 → **실행 환경**
- **명령줄:** `iamceo doctor` (서버가 꺼져 있어도 돕니다. 기계가 읽을 결과는 `iamceo doctor --json`. 실패한 항목이 하나라도 있으면 종료 코드 1로 끝납니다)

| 항목 | 무엇을 보나 | 문제일 때 |
|---|---|---|
| 서버 | 이 Mac의 IAMCEO 서버가 응답하는가 | IAMCEO 앱을 열고 **이 Mac에서 시작**을 누릅니다. |
| 실행 엔진 | 팀장의 터미널을 붙잡는 herdr-core가 있고 답하는가 | 잠시 뒤에도 그대로면 Mac을 다시 시작합니다. 엔진을 찾지 못하면 앱을 다시 설치합니다(`brew reinstall --cask yehsung/tap/iamceo`). Homebrew는 다시 설치할 때 서버를 내리고 로그인 항목을 지우므로, 끝난 뒤 앱에서 **이 Mac에서 시작**을 한 번 누릅니다(팀장 세션은 이어집니다). |
| Claude Code | 설치됐는가, 로그인 기록이 있는가 | 설치한 뒤 터미널에서 `claude`를 실행해 로그인합니다. |
| Codex | 설치됐는가, 로그인 기록이 있는가(쓰지 않으면 괜찮습니다) | 터미널에서 `codex`를 실행해 로그인합니다. |
| CLI 버전 | 설치된 CLI 버전을 IAMCEO가 시험해 본 적이 있는가 | 아래 '확인되지 않은 CLI 버전'을 보세요. |
| Tailscale | iPhone이 닿을 Tailscale 주소가 있는가 | 메뉴 막대에서 Tailscale을 켭니다. |
| 자동 시작 | 서버가 로그인 항목으로 등록돼 있는가 | 앱에서 **이 Mac에서 시작**을 다시 누릅니다. |
| 백업 | 마지막 정기 백업이 언제인가 | Mac과 서버를 켜 두면 하루에 한 번 만듭니다. 실패가 이어지면 저장 공간을 확인합니다. |
| 저장 공간 | 데이터 폴더가 있는 디스크의 남은 공간 | 시스템 설정 → 일반 → 저장 공간에서 공간을 비웁니다. |

로그인 확인은 CLI가 남기는 로그인 기록을 찾는 방식이라 '확인하지 못함'으로 나올 수 있습니다. 그때는 세션을 열 때 확인됩니다.

## 자주 막히는 곳

### 팀장이 시작하자마자 멈춘다

- **로그인을 확인합니다.** 터미널에서 `claude`(또는 `codex`)를 실행했을 때 로그인 화면이 나오면 로그인합니다.
- **터미널에서만 되던 설정인지 봅니다.** 서버는 셸 설정(`~/.zshrc`)의 환경 변수와 PATH를 받지 않습니다. MCP 서버나 훅이 `${GITHUB_TOKEN}` 같은 환경 변수나 pyenv·mise로 설치한 명령에 기대면 여기서는 실패합니다. 값은 CLI 설정 파일의 `env`에, 명령은 절대 경로로 적습니다.
- **팀 화면에서 그 팀장의 터미널을 엽니다.** 실제 화면에 무엇이 떠 있는지 보고 직접 입력할 수 있습니다.

### '폴더 신뢰 확인 창을 읽지 못했습니다'

CLI가 띄운 폴더 신뢰 창의 글자가 IAMCEO가 아는 것과 달라 누르지 않았다는 뜻입니다. 카드의 **터미널 열어 직접 답하기**를 누르고 화살표와 Enter로 답합니다. CLI가 새 버전으로 올라간 직후에 자주 생깁니다(아래 '확인되지 않은 CLI 버전').

### '시작이 늦어지고 있습니다'

팀장을 띄운 뒤 60초가 넘도록 CLI가 준비를 알리지 않았습니다. 승인을 기다리는 것이 아닙니다. 터미널을 열어 무엇이 떠 있는지 확인합니다. 로그인 화면, 업데이트 안내, 처음 보는 확인 창이 흔한 원인입니다.

### 확인되지 않은 CLI 버전

서버는 시작할 때 설치된 Claude Code·Codex의 버전을 읽어 `~/.iamceo/cli-versions.json`에 처음 본 시각과 함께 남기고, IAMCEO가 그 버전의 화면으로 시험해 봤는지 확인합니다. 시험해 본 적 없는 버전이면 점검표의 CLI 버전 항목이 '확인되지 않은 CLI 버전'으로 바뀝니다. 대부분은 그대로 돕니다. 다만 CLI의 확인 창 글자가 바뀌었다면 서버가 그 창을 알아보지 못하고 팀장이 막힘으로 남을 수 있습니다. 그때는 터미널을 열어 직접 답하고, IAMCEO 새 버전이 나오면 올립니다.

### 도구 승인 카드가 닫혔다

권한 방식이 '위험할 때만 묻기'나 '매번 묻기'면 팀장의 도구 승인 창이 결재함에 '도구 승인' 카드로도 뜹니다. **허용**은 이번 한 번만 실행하고, **거절**은 실행하지 않고 메모와 함께 팀장에게 알립니다. 카드는 10분 안에 답하지 않았거나, 터미널에서 먼저 답했거나, 서버가 다시 시작되면 닫힙니다. 닫힌 카드는 다시 열 수 없으니, 팀장이 아직 멈춰 있으면 팀 화면에서 그 팀장의 터미널을 열고 승인 창에 직접 답합니다. 카드가 아예 뜨지 않으면 그 팀장이 '묻지 않기'로 떠 있거나 Codex 팀장인지 봅니다(카드는 Claude Code 팀장에게만 뜹니다).

### 사용 한도에 걸렸다

결재함에 사용 한도 카드가 옵니다. 기다리면 한도가 풀린 뒤 저절로 이어 갑니다.

- **한 모델에만 걸린 한도**면 카드에서 다른 모델을 고르거나 팀장 설정에서 모델을 바꿔 바로 이어 갈 수 있습니다. 같은 대화가 새 모델로 이어집니다.
- **5시간·주간 한도**는 모든 모델이 같이 쓰므로 카드에 모델 선택지가 없습니다. 기다리면 저절로 이어 갑니다.

### 인터넷이나 AI 서비스가 끊겼다

앱에 대기 띠가 뜹니다. 보낸 말은 사라지지 않고, 풀린 뒤 이어서 보냅니다. AI 회사의 서비스가 멈췄다고 판단한 동안 서버는 복구를 확인하려고 내용 없는 확인 요청을 보냅니다.

### 전달이 '전달 확인 필요'로 남았다

보낸 말이 CLI에 들어갔는지 서버가 확인하지 못했다는 뜻입니다. 먼저 **다시 확인**을 누릅니다. 서버는 확실하지 않으면 같은 말을 두 번 넣지 않습니다. 중복될 수 있음을 알고도 다시 보내려면 중복 위험에 동의하고 다시 보냅니다.

### 실행 엔진에 문제가 있다는 안내

팀장의 터미널을 붙잡는 실행 엔진이 답하지 않거나 버전이 맞지 않습니다. 잠시 기다려도 그대로면 Mac을 다시 시작합니다. 서버가 다시 뜨면 꺼진 팀장을 총괄부터 한 명씩 같은 대화로 다시 엽니다.

### 앱과 서버의 버전이 맞지 않는다

앱과 서버가 실제로 맞지 않을 때만 앱에 안내가 뜹니다. 두 가지를 구분해 보여 줍니다.

- **앱을 업데이트하세요:** 앱이 서버보다 오래됐습니다. iPhone은 App Store에서, Mac은 새 버전을 설치합니다.
- **서버가 옛 버전입니다:** 서버가 앱보다 오래됐습니다. 서버가 도는 Mac의 IAMCEO를 새 버전으로 올립니다.

설치 스크립트나 DMG로 Mac 앱을 새 버전으로 바꿨는데 서버가 아직 옛 버전으로 돌고 있으면, 앱이 서버를 새 버전으로 다시 시작할지 한 번 묻습니다. 다시 시작해도 팀장 세션은 실행 엔진이 붙잡고 있어 이어집니다. Homebrew로 올리거나 다시 설치했다면 이 질문 대신 서버가 내려가 있으니 앱에서 **이 Mac에서 시작**을 한 번 누릅니다. → [업그레이드·백업·제거](upgrade-backup-uninstall.md)

### iPhone이 연결되지 않는다

Mac의 Tailscale이 켜져 있는지 먼저 확인합니다. 꺼져 있으면 Mac 앱이 알려 줍니다. 나머지는 [iPhone 연결](iphone.md#연결되지-않을-때)에 있습니다.

iPhone 앱이 '이 iPhone의 Tailscale이 꺼져 있어 보내지 않았습니다'라고 하면 iPhone의 Tailscale 앱에서 연결을 켭니다. 켜면 알아서 다시 연결합니다. Mac 앱에서 **HTTPS 주소**를 켤 수 없다고 나오면 그 줄의 안내를 따릅니다(대개 Tailscale 관리 화면에서 HTTPS 인증서를 켜는 일입니다) → [iPhone 연결](iphone.md#https-주소선택)

## 진단 파일 만들기

문의하거나 이슈를 올릴 때 진단 파일을 붙이면 원인을 찾기 쉽습니다.

- **앱:** 설정 → AI 모델 → 실행 환경의 **진단 파일 만들기** (이 Mac에서 연결했을 때)
- **명령줄:** `iamceo diagnose`

`~/.iamceo/diagnostics/<시각>/` 폴더와 같은 이름의 `.zip`이 생깁니다. 가장 최근 다섯 개만 남깁니다.

| 들어가는 것 | 들어가지 않는 것 |
|---|---|
| 서버·실행 엔진·CLI·macOS 버전(앱에서 만들면 앱 버전도), 접속한 앱의 버전 | 대화·보고·결재·할 일·자료의 본문 |
| 점검표 결과, 서비스 상태 | 첨부 파일 |
| 서버 로그의 끝부분(아는 비밀은 가림) | 접속 코드, 팀장 열쇠, 알림 토큰 |
| 멈춤·재시작 기록, 충돌 보고 파일의 이름 | 환경 변수의 값 |
| 백업 상태, DB의 상태 요약(ID·상태·시각·개수), 설정 값 | |
| 접속 주소(Tailscale 주소 포함)와 포트, 데이터 폴더와 실행 파일의 경로(사용자 이름 포함) | |

로그와 요약에는 사용자 이름이 든 파일 경로, Tailscale 주소, 프로젝트 이름이 남아 있을 수 있습니다. 공개된 곳에 올리기 전에 한 번 열어 봅니다. 취약점이라면 공개 이슈가 아니라 [SECURITY.md](../../SECURITY.md)의 방법으로 알려 주세요.

## 로그

서버 로그는 `~/.iamceo/logs/server.log`와 `server.err.log`에 있습니다. 줄마다 받은 시각이 붙고, 크기가 차면 지난 파일로 넘어갑니다.

## 역할 지침 고치기

총괄·팀장·본사 AI가 받는 역할 지침에 규칙을 더하거나, 지침을 통째로 바꿀 수 있습니다. 파일 이름의 종류는 총괄이 `conductor`, 팀장이 `worker`, 본사 AI가 `root`입니다.

**규칙을 더하기(권합니다).** 더할 규칙만 `~/.iamceo/roles/<종류>.extra.md`에 씁니다. 기본 지침 끝에 붙고, IAMCEO 새 버전의 지침 개선도 그대로 받습니다.

```sh
mkdir -p ~/.iamceo/roles
printf '%s\n' '## 우리 팀 규칙' '- PR 을 만들기 전에 시험을 돌린다.' > ~/.iamceo/roles/worker.extra.md
```

**통째로 바꾸기.** 기본 지침을 꺼내 고친 뒤 이름을 바꿔 두면 그 파일을 씁니다.

```sh
iamceo roles export
cd ~/.iamceo/roles
cp worker.example.md worker.md   # 총괄은 conductor, 본사 AI는 root
# worker.md 를 고칩니다. 첫 줄은 지우지 않습니다
```

- 고친 파일(`worker.md`)은 기본 지침 **전체를 대신합니다**. 합쳐지지 않으므로 꺼낸 기본 파일에서 고칩니다. 그 뒤에 나오는 IAMCEO 새 버전의 지침 개선은 자동으로 들어오지 않습니다.
- 꺼낸 파일의 첫 줄은 그때의 기본 지침을 기억하는 표지입니다. 새 버전에서 기본 지침이 바뀌면 설정의 실행 환경(`iamceo doctor`)에 '고쳐 쓴 역할 지침'이 확인 필요로 뜨고 서버 로그에도 남습니다. `roles export`로 다시 꺼내 바뀐 곳을 옮긴 뒤 첫 줄을 새 파일의 것으로 바꾸면 사라집니다. 규칙을 더하기만 했다면 그 부분을 `worker.extra.md`로 옮기고 `worker.md`는 치우는 편이 낫습니다.
- `worker.extra.md`는 `worker.md`가 있어도 그 끝에 붙습니다.
- 서버를 다시 켤 필요는 없습니다. 이미 떠 있는 세션은 옛 지침 그대로이고, 잠재웠다 깨우면 새 지침으로 뜹니다.
- 지침을 바꿔도 서버가 강제하는 규칙(출처 표시, 대표 말 대조, 파일 경로 검사)은 그대로입니다.
- 통째로 바꾼 지침에 '승인'이라는 낱말이 없으면 서버 로그와 실행 환경에 경고가 남습니다.
- 보고 언어를 English로 골랐다면, 고친 지침에도 영어로 쓰라는 줄이 맨 끝에 붙습니다.
- 고친 지침(`~/.iamceo/roles`)은 백업에 들어가지 않습니다. 새 Mac으로 옮기거나 복원할 때는 그 폴더를 따로 복사합니다. → [업그레이드·백업·제거](upgrade-backup-uninstall.md#새-mac에서-백업으로-시작하기)

자리표시(`{{PROJECT}}`, `{{NAME}}` 등)와 자세한 규칙은 [운영 모델](../operating-model.md#역할-템플릿-고치기)에 있습니다.

# 업그레이드·백업·제거

[English](upgrade-backup-uninstall.en.md) · [사용자 문서 목록](README.md)

아래 `iamceo`는 앱 안의 명령줄 도구(`/Applications/IAMCEO.app/Contents/Resources/runtime/iamceo`)입니다 → [시작하기](getting-started.md#명령줄-도구)

## 새 버전이 나왔는지 알기

- **Mac 앱:** 실행 중일 때 하루에 한 번 GitHub에 최신 릴리스를 묻습니다. 새 버전이 있으면 **설정 → 연결 → 앱**에 '새 버전 있음' 줄이 생기고, **받기**를 누르면 릴리스 페이지가 열립니다. 알리기만 하고 저절로 받거나 설치하지는 않습니다. 이 확인 요청에 무엇이 담기는지는 [개인정보 처리방침](../../PRIVACY.md)에 있습니다.
- **iPhone 앱:** App Store가 업데이트를 맡습니다.

## 새 버전으로 올리기

설치한 방법대로 올립니다. 어느 방법이든 데이터(`~/.iamceo`)는 그대로입니다.

| 설치한 방법 | 올리는 법 |
|---|---|
| Homebrew | `brew upgrade --cask iamceo`. Homebrew는 올리거나 다시 설치할 때 서버를 내리고 로그인 항목을 지웁니다. 끝난 뒤 앱에서 **이 Mac에서 시작**을 한 번 누릅니다(팀장 세션은 이어집니다) |
| 설치 스크립트·DMG | IAMCEO 앱을 종료한 뒤 `iamceo upgrade` (또는 설치 스크립트를 다시 실행하거나 새 DMG의 앱으로 바꿉니다) |

`iamceo upgrade`는 다음 순서로 바꿉니다.

1. 최신 릴리스(또는 `--version v0.2.4`처럼 정한 버전)를 받아 체크섬, 배포자 서명, Apple 공증을 확인합니다.
2. **지금 DB의 사본으로 새 버전을 미리 돌려 봅니다.** 원본은 읽기만 합니다. 미리 돌려 보기가 실패하면 아무것도 바꾸지 않습니다.
3. 직전 버전을 `~/.iamceo/upgrades/<번호>/`에 기록합니다(서비스 설정, DB 사본, 이전 앱).
4. 서버를 내리고 앱을 바꾼 뒤 다시 올려 준비됐는지 확인합니다. **정해진 시간 안에 준비되지 않으면 스스로 직전 버전으로 되돌립니다.**

`iamceo upgrade --dry-run`은 무엇을 할지 보여 주기만 합니다. 실행 중인 앱은 바꾸지 않으므로 먼저 앱을 종료합니다. Homebrew로 설치한 앱은 Homebrew 기록과 맞도록 `brew upgrade`로 올리라고 안내합니다. 지금보다 낮은 버전으로는 바꾸지 않습니다. 돌아가려면 아래 `iamceo rollback`을 씁니다.

| 옵션 | 하는 일 |
|---|---|
| `--version v0.2.4` | 최신 대신 이 버전으로 올립니다 |
| `--dry-run` | 무엇을 할지 보여 주기만 합니다 |
| `--timeout <초>` | 새 버전이 준비되기를 기다리는 시간(10~3600초, 기본 120초). 미리 돌려 보기에서 서버가 늦게 떴으면 그에 맞춰 스스로 늘립니다 |
| `--from <주소 또는 폴더>` | GitHub 대신 이 자리의 릴리스 파일(`SHA256SUMS`와 DMG)을 씁니다. `https://`, `file://`, 폴더 경로(상대 경로는 지금 폴더 기준)를 받습니다 |
| `--force` | Homebrew로 설치한 앱도 이 명령으로 바꿉니다(권하지 않습니다) |
| `--allow-downgrade` | 지금보다 낮은 버전으로 바꾸는 것을 허용합니다 |
| `--skip-rehearsal` | DB 사본으로 미리 돌려 보기를 건너뜁니다(권하지 않습니다) |

소스(git 체크아웃)에서 서버를 돌린다면 버전 대신 커밋으로 올립니다: `iamceo upgrade <커밋>`. 앞으로만 가는 커밋만 받고, 체크아웃에 커밋하지 않은 변경이 있으면 거절합니다.

### 앱을 바꾼 뒤의 서버

- **Homebrew:** `brew upgrade`·`brew reinstall`은 앱을 바꾸기 전에 서버를 내리고 로그인 항목을 지웁니다. 끝난 뒤 IAMCEO 앱을 열고 **이 Mac에서 시작**을 한 번 누르면 새 버전의 서버가 등록됩니다. 팀장 세션은 실행 엔진이 붙잡고 있어 그대로 이어집니다.
- **설치 스크립트·DMG:** 앱만 바꾸면 서버는 다시 시작하기 전까지 옛 버전으로 계속 돕니다. Mac 앱이 이것을 알아보고 **서버를 새 버전으로 다시 시작할까요?**를 한 번 묻습니다. **다시 시작**을 누르면 앱에 든 새 서버로 바꿉니다. 나중에 하려면 **설정 → 연결 → 접속**의 '새 버전으로 다시 시작' 줄을 씁니다. 팀장 세션은 실행 엔진이 붙잡고 있어 서버가 다시 시작해도 이어집니다.

이 질문은 앱이 직접 관리하는 설치(앱으로 설치하고 **이 Mac에서 시작**으로 등록한 서버)에서만 나옵니다. 소스에서 직접 띄운 서버에는 묻지 않습니다.

### 앱과 서버가 맞지 않을 때

앱과 서버가 실제로 맞지 않을 때만 안내가 뜹니다. '앱을 업데이트하세요'는 앱이 오래된 경우, '서버가 옛 버전입니다'는 서버가 오래된 경우입니다. 그 밖에는 버전이 달라도 아무것도 띄우지 않습니다.

## 직전 버전으로 되돌리기

```sh
iamceo rollback --dry-run   # 무엇을 되돌릴지 먼저 봅니다
iamceo rollback
```

마지막 `iamceo upgrade` 전의 버전으로 돌아갑니다. 앱을 먼저 종료합니다. 옵션은 `--yes`(아래), `--dry-run`, `--timeout <초>`(되돌린 버전이 준비되기를 기다리는 시간)입니다. 무엇을 되돌리는지 보일 때 지금 도는 버전과 그 업그레이드를 기록한 시각을 함께 보입니다.

- **지금 도는 버전이 그 업그레이드가 올린 버전일 때만 되돌립니다.** 그 뒤에 DMG·설치 스크립트·Homebrew(소스라면 직접 git)로 버전을 바꿨다면, 여러 버전을 건너뛰어 되돌리거나 오래된 DB 사본을 쓰지 않도록 아무것도 바꾸지 않고 거절합니다.
- 새 버전이 DB 구조를 올렸다면, 업그레이드 전에 떠 둔 DB 사본으로 함께 되돌립니다. 이때는 `--yes`를 붙여야 진행합니다.
- 그 경우 **업그레이드 뒤에 쌓인 대화와 결재는 되돌린 DB에 들어가지 않습니다.** 지우지 않고 `~/.iamceo/upgrades/<번호>/after-upgrade-<시각>/`에 따로 남기며, 오래된 업그레이드 기록을 정리할 때도 이 폴더는 지우지 않습니다. 되돌린 뒤 그 자리를 안내합니다.
- 되돌리기는 앱(소스라면 커밋)을 먼저 되돌리고 DB를 바꿉니다. 도중에 실패하면 바꾼 것을 모두 원래대로 돌리고 서버를 다시 올립니다. 기록은 그대로라 원인을 고친 뒤 다시 `iamceo rollback`을 할 수 있습니다. 소스 체크아웃에 커밋하지 않은 변경이 있으면 서버를 내리기 전에 거절합니다.
- 업그레이드 기록(`~/.iamceo/upgrades`)은 가장 최근 두 번 것만 통째로 남기고, 그보다 오래된 것은 큰 사본(이전 앱, 업그레이드 전 DB 사본)을 지웁니다. 한 번 되돌린 업그레이드는 다시 되돌리지 않습니다.
- 자동 되돌리기는 새 버전이 뜨지 못했을 때만 합니다. 이미 잘 돌고 있는 버전을 되돌릴지는 직접 정합니다.
- **HTTPS 주소를 켜 두었다면 되돌리기 전에 끕니다.** 되돌린 버전은 그 주소를 모르는 버전일 수 있고, 그 버전은 HTTPS 주소로 들어온 다른 기기의 요청을 이 Mac의 요청으로 볼 수 있습니다. 끄지 못하면 되돌리지 않고 까닭을 알립니다. 되돌린 뒤 다시 쓰려면 설정 → 연결 → HTTPS 주소에서 켜고, 그 주소로 연결했던 iPhone은 새 QR로 다시 연결합니다. 지금보다 낮은 버전으로 바꾸는 `iamceo upgrade --allow-downgrade`도 같고, 앞으로 가는 업그레이드는 끄지 않습니다.

## 백업

서버는 켜져 있는 동안 **하루에 한 번** `~/.iamceo/backups`에 검증한 백업을 만듭니다. 일별 7개와 주별 4개를 남깁니다. 마지막 백업이 언제인지는 점검표의 백업 항목(`iamceo doctor`)에 나옵니다.

| 백업에 들어가는 것 | 들어가지 않는 것(따로 보관) |
|---|---|
| DB(대화, 결재, 할 일, 업무, 자료 목록, 설정) | 프로젝트 작업 폴더의 파일(내 코드는 git 등으로 따로) |
| 대화와 자료가 쓰는 첨부 파일 | Claude Code·Codex의 로그인과 세션 기록 |
| `config.json`(접속 코드 포함), 있으면 `apns.json` | iPhone 알림 키(`.p8`) |
| | `~/.iamceo/roles`에 고쳐 둔 역할 지침(`<종류>.md`, `<종류>.extra.md`) |

- 백업은 파일마다 해시를 적고 DB 무결성을 검사합니다.
- **백업에는 접속 코드가 그대로 들어 있습니다.** 다른 곳으로 옮기면 비밀번호처럼 다룹니다. QR로 연결한 기기의 열쇠는 해시만 들어갑니다.
- 백업은 같은 디스크에 있으므로 디스크 고장에는 대비하지 못합니다. 가장 최근 `snapshot-<번호>` 폴더를 외장 디스크 같은 다른 곳에 복사해 두세요.
- `iamceo backup`은 데이터 폴더를 혼자 쓸 수 있을 때만 됩니다. 서버가 켜져 있으면 '켜져 있는 서버가 데이터 폴더를 쓰고 있어 지금 백업하지 않았습니다'로 거절되므로, 그때는 서버가 매일 만드는 백업을 씁니다.
- 역할 지침을 고쳐 썼거나 규칙을 더했다면(`~/.iamceo/roles/<종류>.md`·`<종류>.extra.md`, [문제 해결](troubleshooting.md) 참고) 그 폴더는 백업에 들어가지 않습니다. 복원하면 기본 지침으로 돌아가므로 따로 복사해 둡니다.

## 새 Mac에서 백업으로 시작하기

새 Mac으로 옮기거나 Mac을 다시 설치했을 때, 백업에서 대화·결재·자료를 되살립니다.

1. **옛 Mac에서** 가장 최근 백업 폴더(`~/.iamceo/backups/snapshot-<번호>`, 또는 `iamceo backup --directory <외장 디스크>`로 만든 것)를 새 Mac으로 복사합니다. 새 Mac에서는 데이터 폴더(`~/.iamceo`) **밖**, 예를 들어 데스크탑에 둡니다. 백업에는 접속 코드가 들어 있으니 비밀번호처럼 다룹니다. 역할 지침을 고쳐 썼다면 `~/.iamceo/roles` 폴더도 함께 복사해 두었다가, 복원을 마친 뒤 새 Mac의 `~/.iamceo/roles`에 넣습니다. 옛 Mac을 계속 쓸 생각이 아니면, 복사한 뒤 옛 Mac에서 `iamceo uninstall`로 IAMCEO를 멈춥니다(데이터는 남습니다).
2. **새 Mac에서** IAMCEO, Claude Code(로그인까지), 필요하면 Codex와 Tailscale을 설치합니다. 아직 **이 Mac에서 시작**은 누르지 않습니다. 누르면 새 데이터 폴더가 생겨 복원이 거절됩니다. 이미 눌렀고 새 Mac에 남길 데이터가 없다면 `iamceo uninstall --purge`로 그 폴더를 지운 뒤 복원합니다.
3. 앱이 쓰는 데이터 폴더(`~/.iamceo`)로 복원합니다. 복원은 **비어 있거나 아직 없는 폴더**에만 되고, 발신을 꺼 둔 채로 만듭니다. 옛 Mac과 사용자 이름이 같아 백업을 만든 경로와 같아도 됩니다. 데이터가 남아 있는 폴더는 덮어쓰지 않고 거절합니다.

   ```sh
   iamceo restore ~/Desktop/snapshot-<번호> --destination ~/.iamceo
   iamceo restore reconcile
   iamceo restore resume
   ```

   `reconcile`과 `resume`은 `~/.iamceo`를 다룹니다(다른 폴더에 복원했다면 `IAMCEO_HOME`을 그 폴더로 정합니다). `reconcile`은 백업을 만들 때 진행 중이던 전달과 알림을 보수적으로 정리하고(다시 보내지 않고 멈춰 둡니다), `resume`은 그 뒤에 발신을 허용하고 백업 때 실행이 켜져 있던 프로젝트를 다시 켭니다. 둘 다 서버가 꺼진 채로 하고, 서버나 AI를 직접 띄우지 않습니다. 옛 Mac과 새 Mac을 함께 쓸 생각이면 첫 줄에 `--clone`을 붙여 새 서버로 복원합니다. 복제본은 옛 Mac에 연결돼 있던 기기의 열쇠를 받지 않고, 접속 코드도 새로 만듭니다(`iamceo open`으로 확인).
4. IAMCEO 앱을 열고 **이 Mac에서 시작**을 누릅니다. 복원한 데이터와 접속 코드로 서버가 로그인 항목에 등록되고 앱이 바로 연결됩니다.
5. 프로젝트의 작업 폴더(내 코드)를 새 Mac의 같은 자리에 두거나, 프로젝트 관리에서 폴더를 새 자리로 바꿉니다. CLI의 세션 기록은 백업에 없으므로 팀장은 새 세션으로 열립니다.
6. iPhone은 주소가 바뀌었으므로 새 QR로 다시 연결합니다. 복원한 서버는 알림 기기를 모두 꺼 두므로, 알림을 쓰던 기기는 알림을 다시 켭니다.

## 기록은 얼마나 남나

- **대화, 결재, 할 일, 자료는 내가 지우기 전까지 남습니다.**
- 서버가 안에서만 쓰는 기록은 기한이 지나면 스스로 정리합니다. AI 세션에 넣은 글의 사본은 그 전달이 끝나고 30일 뒤에 비우고(무엇을 보냈는지의 해시는 남깁니다), 실행 기록과 처리 영수증은 끝나고 90일 뒤에 지웁니다. 끝나지 않은 일의 기록은 지우지 않습니다.
- 서버 로그는 크기가 차면 지난 파일로 넘어가며, 몇 개만 남깁니다. 진단 파일은 가장 최근 다섯 개만 남깁니다.

## 프로젝트 내보내기와 지우기

보관함에 넣은 프로젝트는 프로젝트 단위로 내보내거나 지울 수 있습니다.

- **내보내기:** 그 프로젝트의 대화, 결재, 할 일, 업무, 자료와 첨부 원본을 zip 파일 하나로 받습니다. 접속 코드, 팀장 열쇠, 전달 내부 기록은 넣지 않습니다. 이 Mac에서 연결한 앱에서만 됩니다. 대화 내용이 그대로 들어 있으니 보관에 주의합니다.
- **지우기:** 보관한 프로젝트만 지울 수 있습니다. 지우기 전에 한 번 더 확인하고, 지운 프로젝트는 되살릴 수 없습니다. 필요하면 먼저 내보냅니다. 그 프로젝트의 첨부 파일도 함께 지우고, 작업 폴더(내 코드)는 지우지 않습니다. 이미 만든 백업에는 지운 프로젝트가 남아 있다가, 오래된 백업이 차례로 지워지면서(길게는 약 4주) 사라집니다. `iamceo upgrade`가 남긴 업그레이드 기록의 DB 사본(최근 두 번)에도 남습니다.
- 본사는 보관하거나 지울 수 없습니다.

## 이 Mac에서 완전히 멈추기(제거)

앱을 휴지통에 버리는 것만으로는 이미 떠 있는 서버와 AI 세션이 남을 수 있습니다. 먼저 IAMCEO를 완전히 멈춘 뒤 앱을 지웁니다.

- **앱:** Mac 앱의 **설정 → 연결** 맨 아래 **이 Mac에서 완전히 멈추기**. 앱으로 설치했고, 등록된 로그인 서비스가 없거나 앱이 등록한 것일 때만 보입니다(소스에서 돌리는 서버나 옛 명령줄 설치의 서비스가 있으면 보이지 않습니다). 멈춘 뒤에 나타나는 **데이터도 지우기**로 데이터까지 지울 수 있습니다(한 번 더 확인합니다). 다른 Mac의 서버에 연결해 있으면 이 Mac의 IAMCEO와 데이터만 다루고, 그 서버와의 연결은 그대로 둡니다.
- **명령줄:** `iamceo uninstall` (`--dry-run`으로 무엇을 할지 먼저 볼 수 있습니다. `--yes`는 확인을 묻지 않습니다)

차례는 이렇습니다.

0. 먼저 이 명령으로 끌 수 있는 서버인지 봅니다. 다른 설치(옛 명령줄 설치, 소스 체크아웃)의 로그인 서비스가 같은 데이터 폴더로 떠 있거나, 서비스 밖에서 직접 띄운 서버가 떠 있으면 **아무것도 하지 않고** 거절합니다(팀장도 재우지 않습니다).
1. HTTPS 주소를 켜 두었다면 먼저 끕니다(이 서버가 만든 `tailscale serve` 설정만 지웁니다. 그 설정은 Tailscale 쪽에 남으므로 제거한 뒤에도 남지 않게 합니다). 끄지 못하면 터미널에서 `tailscale serve --https=443 off`로 끄라고 알리고 나머지는 계속합니다. 그다음 서버가 떠 있으면 IAMCEO가 관리하는 팀장을 모두 재웁니다. 내가 직접 띄워 붙인 세션은 건드리지 않습니다.
2. 로그인 항목으로 등록한 서버를 해제합니다(서버가 내려갑니다). 앱이 등록한 서비스만 해제하고 다른 설치의 서비스는 건드리지 않습니다. 소스에서 돌리는 서버의 서비스는 `--include-checkout`을 붙였을 때만 해제하고, 그 서비스 설정은 지우지 않고 `~/Library/Application Support/IAMCEO/service-backup/`에 사본으로 남깁니다.
3. 실행 엔진의 터미널을 모두 끝내고 엔진을 끕니다. 엔진이 끝나지 않으면 Mac을 다시 시작하라고 알립니다.
4. **데이터는 기본으로 남깁니다.** 지우려면 `iamceo uninstall --purge`를 쓰고, 한 번 더 확인합니다(터미널에서는 '지우기'를 입력합니다). 데이터 폴더(`~/.iamceo`)를 통째로 지우므로 **그 안의 백업도 함께 사라집니다.** `iamceo backup --directory`로 바깥에 만든 백업은 지우지 않습니다. 필요한 백업은 먼저 다른 곳에 복사합니다. DB와 접속 코드가 든 설정 파일이 함께 있는 폴더만 지우고, 기본 자리(`~/.iamceo`)도 등록된 서비스의 폴더도 아니면 `--yes`를 붙여도 경로를 그대로 입력해야 지웁니다.

그다음 앱을 지웁니다. Homebrew로 설치했다면 `brew uninstall --cask iamceo`, 아니면 응용 프로그램 폴더의 IAMCEO를 휴지통으로 옮깁니다. `brew uninstall --zap --cask iamceo`는 앱을 지운 뒤 앱에 든 `iamceo uninstall --purge --yes`로 모든 팀장과 실행 엔진을 멈추고 데이터 폴더(그 안의 백업 포함)를 지웁니다. 되돌릴 수 없습니다. 그 단계가 실패하거나, 다른 설치(소스에서 돌리는 서버 등)의 로그인 서비스가 남아 있어 멈추지 않았을 때는 데이터 폴더를 휴지통으로만 옮깁니다.

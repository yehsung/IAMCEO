01 / ONE RUNTIME

세 역할, 하나의 실행 구조.

앱은 조작 창구, IAMCEO는 업무 관리, herdr-core는 실행 기반입니다. Mac 앱이 꺼져 있어도 iPhone은 호스트 데몬에 직접 붙습니다.

IAMCEO

무슨 일을 누가 맡았는가

목표·담당권·의존성·결정·자료·인계를 저장합니다. 화면은 이 기록을 읽으므로 모든 보고를 총괄 채팅으로 다시 요약하지 않습니다.

HERDR-CORE

어느 프로그램이 살아 있는가

터미널 실행·입출력·접속·상태를 제공합니다. 기존 Herdr TUI와 별개이며, 기존 pane/workspace API와 호환되지 않습니다.

OFFICIAL CLI

실제로 어떻게 일을 하는가

추론 루프·도구·캐시·압축·원래 세션은 공식 CLI에 맡깁니다. 같은 계정·설정·작업 경로를 사용하고 API 과금으로 자동 전환하지 않습니다.

02 / WORK OWNERSHIP

부서보다 업무, 인원보다 책임.

고정된 개발 팀장 하나로 몰지 않습니다. 독립적인 업무마다 담당자를 두고, 관련된 일은 기존 담당자가 이어갑니다.

대표 · 사용자

총괄에 목표를 맡기거나 특정 팀장에게 직접 지시합니다. 승인·선택·정보 제공을 결재함에서 처리하고 자료에 피드백합니다.

총괄 · 기본 Claude

분해·배정·우선순위·의존성·충돌 조율만 맡습니다. 작은 코드 수정도 팀장에게 위임합니다. 실패·의존성 해소·중요 결정 때만 깨우고 일상 진행은 UI에 직접 반영합니다.

팀장 · 업무별 Claude / Codex

범위·파일 소유권·완료 조건을 받아 실행합니다. 필요할 때 CLI가 지원하는 하위 에이전트를 사용합니다. 검토가 필요하면 독립 담당을 추가합니다.

프로세스 부모와 업무 조직도는 분리합니다. 팀장은 IAMCEO 데몬이 소유합니다. CLI 안에서 시작해 부모가 생기는 경우 --outlive-parent를 적용합니다. 총괄 교체·종료는 팀장 종료 사유가 아닙니다. 일시적인 보조 프로세스는 업무 종료 시 정리합니다.
병렬 변경 충돌을 먼저 관리합니다. 작업 범위·공유 파일을 기록하고, 겹치는 쓰기는 순서를 정하거나 worktree로 분리합니다. 총괄은 전체 로그 대신 변경 요약·검증 근거·충돌만 받습니다.
03 / STATUS IS NOT COMPLETION

CLI 상태와 업무 완료는 다릅니다.

OSC 7501은 화면을 읽지 않고 실행 상태를 알게 해줍니다. 그러나 승인 내용이나 업무 완료 근거까지 대신하지는 않습니다.

지원 확인

Claude Code · Codex

Claude Code 2.1.295, Codex CLI 0.163.0부터 지원이 확인됩니다. 현재 로컬은 각각 2.1.318 / 0.166.0. 실제 터미널에서 상태 수신을 시작 시 진단합니다. 설치 버전만으로 전체 시나리오 통과를 가정하지 않습니다.

working · 실행 중blocked · 응답 필요idle / done · 턴 상태

지원 신호가 없으면 ‘상태 미확인’으로 표시합니다. 자동으로 idle이나 완료라고 간주하지 않습니다.

IAMCEO가 설계할 부분

업무·결정·결과의 기준

업무는 대기 → 진행 → 응답 대기 / 검토 → 완료로 관리합니다. 완료에는 산출물과 완료 조건 확인이 필요합니다. CLI의 done·idle은 백그라운드 도구와 모든 하위 작업의 종료를 뜻하지 않습니다.

보고 API 예: task.accept, task.report, decision.request, artifact.register. 이름은 제안이며 기존 MCP 도구와 정합성을 맞춥니다.

결재함 유형들어오는 정보응답과 실행
업무 승인배포·범위 변경 등의 요청, 근거, 영향, taskId승인·거절·보류. 결정 기록과 해당 작업의 실행 정책 연결.
선택·질문·정보 요청선택지·자유 답변·첨부 요청, 답이 필요한 이유답변을 원래 담당자에게 전달. 답변을 도구 실행 승인으로 해석하지 않음.
CLI 도구 권한공식 hook/연동으로 확보한 원문·행위·세션·요청 식별자실제 지원하는 응답 경로만 사용. 확인 불가능하면 원래 터미널을 열어 직접 처리. 임의 Enter·force로 승인하지 않음.
최초 버전의 경계: 자체 업무 결재는 MCP로 구현합니다. 두 CLI의 도구 권한 요청은 별도 어댑터로 검증합니다. 구조화된 원격 응답을 보장하지 못하는 요청은 같은 Mac·iPhone 앱의 터미널 보기로 연결합니다. 이를 ‘완전한 결재 통합’으로 표시하지 않습니다.
04 / CONTINUITY WITHOUT PRETENDING

모델이 바뀌어도, 업무는 남습니다.

담당자의 내부 컨텍스트를 옮기는 대신 목표·결정·자료·진행 상황을 지속해서 보존합니다. CLI 간 교체는 새 담당 세션을 만드는 방식이 기본입니다.

같은 CLI에서 재개

공식 resume·지원되는 모델 설정을 사용합니다. 세션 ID와 실제 설정을 기록하고 기존 세션이 종료됐는지 확인합니다. 실행 중인 대화의 모델 변경은 안전 지점에서 적용합니다.

대화 기록 복구와 캐시 적중은 별개입니다. 살아 있는 도구 프로세스가 복원된다고 약속하지 않습니다.

Claude ↔ Codex 교체

새 팀장 또는 새 총괄 세션을 시작하고 인계 묶음을 제공합니다. 목표·제약·결정·수정 파일·검증·미완료 항목·다음 행동·원문 링크를 포함합니다. KV 캐시·숨은 추론을 이전하지 않습니다.

새 프로젝트의 총괄도 처음부터 Codex로 선택할 수 있습니다. 계정 한도 도달은 대기·알림으로 처리하고 교체는 사용자 정책에 따릅니다.

  1. 기존 담당을 안전 지점에 둡니다.

    새 실행 전달을 멈추고 진행 중인 부작용과 대기 승인을 확인합니다. 이미 수행 중인 파일 쓰기를 권한 토큰 회수만으로 멈출 수는 없습니다.

  2. 새 담당은 인계 내용을 확인합니다.

    초기에는 실행·배정 권한 없이 요약과 자료를 읽고 이해한 범위·남은 일을 확인합니다. 아직 담당권을 옮기지 않습니다.

  3. 담당권을 한 번 전환합니다.

    DB 트랜잭션으로 owner와 generation을 변경하고 새 세션에 토큰을 부여합니다. 이전 세대의 보고·명령은 현재 업무를 변경하지 못합니다. 기존 담당이 안전하게 멈춘 것이 확인된 뒤 쓰기를 허용합니다.

  4. 실패하면 원래 담당을 유지합니다.

    인수 실패는 새 세션 정리로 끝냅니다. 전환 이후 실패는 기록을 남기고 복구를 결정합니다. 총괄을 바꾸어도 기존 팀장과 작업 연결은 그대로 유지합니다.

05 / FAILURE BOUNDARIES

창을 닫는 일과, 작업을 잃는 일을 구분합니다.

코어의 터미널 보존 기능 위에 업무 복구를 얹습니다. 연결이 끊겼다는 이유만으로 새 직원이나 새 작업을 만들지 않습니다.

무슨 일이 생겼나실행 상태복구 동작
Mac·폰 앱 종료 / 네트워크 끊김호스트와 CLI가 살아 있으면 작업 지속앱 재접속 → IAMCEO 이벤트 커서·스냅샷 갱신. 초안·접수 확인 중 상태 보존.
IAMCEO 데몬 재시작독립 core·holder의 CLI는 유지 목표단일 데몬 소유 잠금 → terminal 목록과 DB 대조 → 대기 보고 수신·입력 큐 복구. 새 작업 중복 실행 금지.
herdr-core 재시작 / 업데이트holder가 살아 있으면 원래 터미널 유지 가능API 재연결·기능 협상·새 스냅샷. core seq는 재시작마다 초기화되므로 IAMCEO의 영속 커서와 분리.
holder / CLI 프로세스 손실해당 실행 중단프로세스·결과·CLI 기록 확인 후 지원되는 resume. 새 세션 세대를 부여. 불확실한 배포·삭제를 자동 반복하지 않음.
Mac 재부팅 / 로그아웃기존 프로세스 생존 보장 없음사용자 서비스 가동 후 재대조. core의 keep 복구는 새 셸이며 원래 에이전트 자동 재실행이 아님.
Mac 절전 / 전원 꺼짐처리·원격 연결 불가 또는 일시 정지폰에 마지막 확인 시각 표시. 작업 중 절전 방지 옵션과 배터리 정책 제공. 복귀 시 실제 생존 상태 확인.

입력 전달은 ‘정확히 한 번’을 추측하지 않습니다.

앱 명령은 commandId로 중복 제거합니다. 하지만 PTY에 글이 들어간 직후 응답을 잃으면 CLI가 받았는지 불확실할 수 있습니다. 전달 상태를 접수·전송 중·CLI 확인·불확실로 구분하고, 불확실한 입력은 자동 재전송하지 않습니다.

IAMCEO 작업 지시에는 deliveryId를 넣고 팀장의 MCP 접수 확인을 받습니다. 키 입력·외부 부작용까지 원자적으로 보장하는 장치는 아닙니다.

터미널 직접 조작과 자동 입력을 조율합니다.

터미널을 직접 제어하는 동안 해당 직원의 자동 전달을 보류합니다. 사용자가 관리 모드로 돌아오면 CLI 상태·대기 요청을 다시 확인하고 큐를 재개합니다. 보기 전용 관찰은 별도로 제공합니다.

코어는 인간 입력이 잠잠해질 때 전송하지만, 그것만으로 업무 단위 입력 경쟁을 해결했다고 간주하지 않습니다.

06 / SAME WORK, TWO DEVICES

같은 기능, 기기에 맞는 배치.

기존 리퀴드 글래스 디자인과 다섯 메뉴를 유지합니다. 채팅은 지시의 창구로 남기고, 진행·결정·결과는 각 화면에서 확인합니다.

macOS · 넓게 비교하고 관리

프로젝트 사이드바 + 홈·결재함·팀·대화·자료. 업무 상세와 자료를 나란히 보고, 필요하면 해당 직원의 터미널을 엽니다. 총괄·모델·연결 설정은 설정 화면에서 관리합니다.

iOS · 밖에서도 동일하게 실행

프로젝트 선택 + 같은 다섯 탭. 업무 생성·담당자 추가·모델 교체·질문 답변·결재·자료 확인·직접 지시·터미널 접근을 동일하게 제공합니다. 설정은 상단 프로젝트 메뉴에 둡니다.

컴퓨터의 기능도 그대로 활용합니다. 에이전트가 이미 가진 셸·MCP·브라우저·시뮬레이터 도구로 호스트를 조작하고 캡처를 자료로 등록합니다. 앱·CLI 간 도구 차이와 macOS 권한을 확인합니다. 별도 컴퓨터 조작 엔진은 기본 구성에 넣지 않습니다.
원격과 알림: Tailscale을 통한 호스트 직접 연결에 기기 페어링·토큰 폐기를 더합니다. APNs는 최소 알림만 보내고 상세 자료는 인증 후 호스트에서 읽습니다. 알림 도착은 호스트가 현재 접속 가능하다는 보장이 아닙니다.

07 / IMPLEMENTATION CONTRACT

기술 경계가 교체 비용을 줄입니다.

플랫폼에 묶이는 부분은 화면과 설치뿐입니다. Windows·Android는 나중에 같은 업무 API를 사용하는 클라이언트로 추가합니다. 실행 호스트의 OS 지원은 별도 검증합니다.

세 연결의 계약

앱 ↔ 업무: commandId·expectedVersion을 가진 명령, 접수 응답, 영속 이벤트 커서와 스냅샷.
업무 ↔ core: terminal 실행·읽기·입력·attach·이벤트. 코어 재시작 시 새 스트림으로 대조.
CLI ↔ 업무: 직원별·세션 세대별 토큰을 가진 MCP. 업무 범위 밖 변경 요청은 거부.

관리 토큰은 OS 샌드박스가 아닙니다. 같은 사용자 권한의 CLI·core는 호스트 파일에 접근할 수 있습니다. 세션 토큰은 업무 API 권한을 제한하며, 실제 파일·명령 권한은 공식 CLI의 권한 정책과 필요시 작업 격리로 관리합니다.
08 / DELIVERY PLAN

실행을 검증하고, 회사 화면을 연결합니다.

설계는 herdr-core 하나로 확정합니다. 구현 중 사용자에게 실행 엔진을 고르게 하지 않습니다.

  1. 01 · CoreClient와 공식 CLI 검증

    고정 버전 hc·전용 상태 경로. Claude/Codex 실행·OSC 수신·추가 지시·중단·attach·한글·MCP·CLI 설정 확인. 앱 종료·core 재시작·holder 손실을 각각 시험. 기동 실패 때 다른 엔진으로 자동 전환하지 않습니다.

  2. 02 · 기존 업무 계층 연결

    기존 store/db·전달 큐·agent-tools·역할 규칙을 검토해 재사용합니다. 새로운 core 어댑터로 terminalId를 관리하고 기존 화면 판독·입력칸 삭제·자동 재시도 가정을 제거합니다. 총괄 수명과 팀장 수명을 분리합니다.

  3. 03 · Mac·iPhone 동일한 수직 기능 구현

    한 업무를 만들고 팀장에게 지시 → 질문 답변 → 실행 캡처 → 검토·완료까지 두 앱에서 같은 API로 구현합니다. 페어링·연결 끊김·재전송·결재 충돌·자료 권한을 검증합니다.

  4. 04 · 교체·복구·설치 완성

    총괄/팀장 Claude↔Codex 인계, 담당권 경쟁, 전달 불확실성, 한도 도달을 시험합니다. 서명·공증·SMAppService·권한·업데이트·APNs·TestFlight 흐름을 새 Mac에서 확인합니다.

현재 데이터와 기존 세션: 기존 Herdr TUI의 pane ID를 hc terminal ID로 바꿔 적지 않습니다. 이전 실행을 정리한 뒤 지원되는 CLI 세션을 새 터미널에서 재개하고 연결 기록을 남깁니다. DB 백업·버전 마이그레이션·롤백 경로를 먼저 준비합니다.
배포: 검증된 herdr-core 빌드와 라이선스·고지를 IAMCEO 설치에 포함하고 버전을 고정합니다. 공급자 CLI는 설치·로그인 안내와 상태 진단을 제공합니다. 기존 사용자 설치·설정을 무단으로 덮어쓰지 않습니다. 포크는 꼭 필요한 수정만 추적하며, 초기에 엔진 소스를 대폭 개조하지 않습니다.

- 대표가 읽거나 복사하거나 확인해야 하는 결과물(문서·대본·표·이미지·영상)은 반드시 `file` 도구로 자료에 올리고, 반환된 id를 `post`의 `file_ids`에 연결한다. 로컬 파일 경로만 말하고 끝내지 않는다. 경로는 자료 연결에 덧붙일 수 있다. 이미 올린 자료가 바뀌면 도구가 허용하는 방식으로 같은 자료를 갱신하거나 새 판을 `file`로 올려 최신 id를 보고에 연결한다.
- 짧은 보고는 `post`, 긴 글은 `file`의 `content`(md). 글로 설명이 길어지거나 비교·흐름·구조·수치·시안처럼 글만으로 보기 힘든 내용은 `file`의 `html`로 한 페이지를 만들어 올리고 그 id를 `post`의 `file_ids`에 잇는다. 대표가 읽고 판단할 비교표·요약 표는 csv 나 마크다운 표가 아니라 `html`이다. "비교표", "표로 정리", "한눈에 보게" 같은 말이면 html 로 올린다. csv 는 대표가 내려받아 쓸 원본 데이터(수십 행 이상)일 때만 쓴다. 외부 사이트에 따로 게시하지 않는다.
- html 은 자체 완결이어야 한다(CDN·일반 외부 요청은 막히고 중첩 iframe 은 지워진다, 스크립트는 인라인만, 이미지는 data:, 격리가 완전하지 않으니 비밀번호·개인정보 같은 민감한 데이터는 싣지 않는다). 기본 스타일 키트가 자동으로 깔리므로 semantic HTML 과 키트 클래스(card, grid, callout, kpi, steps, flow, tabs, tag, compare)만 써도 깔끔하다.
